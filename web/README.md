# Тропник — веб-карта, рельеф и спутник

React/TypeScript приложение с собственным Canvas-движком `CustomMapEngine`.
Основная карта показывает два режима: **«Рельеф»** и **«Спутник»**. Отдельная
3D-сцена не подключается к главному экрану и не загружается заранее.
MapLibre, Leaflet и Protomaps не входят в рабочий runtime карты.

Текущая версия исходников — **0.4.30**. Состав изменений, результаты проверок
и подтверждённая публикация фиксируются в [журнале выпуска](../docs/release-0.4.30.md).
Версия в `package.json` сама по себе не подтверждает развёртывание сайта.

## Разработка и сборка

Требуются Node.js не ниже версии из `engines` и pnpm из `packageManager`.
В CI используются Node 24 и pnpm 11.25.0. Канонический lockfile —
`pnpm-lock.yaml`.

Из этого каталога:

```sh
pnpm install --frozen-lockfile
pnpm dev
```

`pnpm build` собирает Worker/Vinext для Sites, `pnpm start` запускает
собранный Worker локально. Отдельные `pnpm run build:next` и
`pnpm run start:next` сохранены для Next. Публикация выполняется отдельно
после проверки собранной версии.

### Общая сборка карты

Карта показывает геометрию всех подходящих под фильтр маршрутов, а выбранный
маршрут выделяет поверх общего слоя. Обзорный ресурс хранит каждый исходный
сегмент отдельно. При приближении подгружаются точные исходники видимой
области; очередь и память ограничены. После изменения каталога пересоберите
его производные из корня полного репозитория:

```sh
python3 web/scripts/prepare-catalog.py
python3 web/scripts/prepare-editorial-geometry.py --check
node --experimental-strip-types web/scripts/build-trail-overlay.mjs
node --experimental-strip-types web/scripts/build-trail-connections.mjs
node tools/android-build/prepare-catalog.mjs
```

Сборки Pages и Sites проверяют, что общий слой соответствует текущему
каталогу. Карточки без подтверждённой линии не получают искусственную
геометрию. Общий веб-слой подключён в `CustomAtlas`; наличие общего движка
само по себе не добавляет этот контроллер в выпущенный Android APK.

Браузер, автономный просмотрщик и Android используют общий исходный движок.
После изменений его входов, CSS общей карты или версии пакета нужно
пересобрать проверяемые ресурсы **из корня полного репозитория**:

```sh
node tools/android-build/prepare-custom-map.mjs
node web/scripts/prepare-offline.mjs
node web/scripts/stamp-service-worker.mjs
node tools/android-build/prepare-custom-map.mjs --check
node web/scripts/verify-custom-map.mjs
node web/scripts/verify-map-shell.mjs
```

В commit входят оба результата `web/public/custom-map/` и
`android/app/src/main/assets/custom-map/`, контрольные суммы и service worker.
Проверка `--check` заново строит результат во временном каталоге и сравнивает
его с сохранёнными байтами. Обычный build отклоняет устаревший общий runtime;
web-only checkout Sites не заменяет генерацию в полном репозитории.

Если изменился отдельный renderer ландшафта или его bootstrap, перед этим
нужно выполнить `node web/scripts/build-landscape.mjs` и
`python3 tools/android-build/prepare-landscape.py` из полного репозитория.
Самостоятельная сцена Бзерпинского района сохраняется в автономном пакете.

### Статический GitHub Pages

Из корня полного репозитория:

```sh
node tools/pages-preview/fetch-apk.mjs
node tools/pages-preview/build.mjs --base /tropnik/ --origin https://orewn.github.io
```

Сборка проверяет локальные байты существующего APK по опубликованному
манифесту, создаёт статические страницы и проверяет ресурсы и HTTP-маршруты.
APK не дублируется в архив Pages: кнопка ведёт на закреплённый GitHub Release.
Наличие локального архива не означает успешную публикацию.

## Главные части

- `lib/custom-map-engine.ts` — камера, жесты, композиция слоёв, подписи и
  состояние загрузки. Перерисовка запускается по изменениям; постоянного
  цикла кадров в покое нет.
- `lib/custom-map-tiles.ts` и `custom-map-tiles.worker.ts` — ограниченные
  очереди, кэш, загрузка, декодирование и подготовка картографических тайлов.
- `lib/custom-map-relief.ts` — отмывка и горизонтали по измеренным высотам.
  Увеличение масштаба не добавляет новые измерения.
- `components/CustomAtlas.tsx` — управление картой, слои, восстановление после
  ошибок и согласование карты с карточкой маршрута.
- `lib/map-direction-layout.ts` — общие препятствия для подписей карты и
  кнопок направлений, включая соседние панели и раскрытые меню.
- `public/custom-map/manifest.json` — проверяемые исходники и ресурсы общей
  web/Android сборки.
- `lib/offline-map.ts`, `public/sw.js` и `public/offline-viewer.html` —
  загрузка и проверка ограниченного автономного пакета, оболочка и просмотрщик.

## Данные и доступные возможности

Рельеф использует реальные DEM-данные; картографические объекты и маршруты
сохраняют происхождение и уведомления об авторстве. Собственными являются
движок, отрисовка и интерфейс. Ссылки на источники доступны в `/sources`.
Спутниковые снимки не являются текущим наблюдением условий на маршруте.

Подробная автономная карта ограничена Бзерпинским районом. Локальный обзор
России и сохранённые карточки не означают подробное офлайн-покрытие всей
страны. Скачивание пакета завершается проверкой размеров и SHA-256 файлов;
условия посещения и доступность маршрутов проверяются отдельно.

GitHub Pages включает карту, каталог, поиск, локальные планы и экспорт.
Серверные действия аккаунтов, групп и сообщений в статическом preview
недоступны и не подменяются фиктивным успехом. Для них нужен отдельно
настроенный Go API, база и соответствующие серверные проверки.

Скачиваемый APK определяется `public/downloads/android-manifest.json`:
сейчас это **0.4.25-preview**, `versionCode 13`, с development/debug подписью.
Обновление общей сборки в исходниках или веб-публикация не изменяет уже
выпущенный APK. Условия установки и фактическая версия показаны на `/android`.

## Проверки качества

Из этого каталога:

```sh
node --experimental-strip-types --test --test-concurrency=1 tests/*.test.mjs
pnpm lint
node node_modules/typescript/bin/tsc -p pages-preview/tsconfig.json --noEmit
```

Полный [Pages workflow](../.github/workflows/pages.yml) дополнительно проверяет
управление на нескольких размерах экрана, композицию карты, переключение
слоёв, плавность и фактическую опубликованную ревизию. Результаты относятся
к конкретному commit и браузерному профилю; аппаратный FPS телефона или
полевую навигацию они не подтверждают. Актуальные статусы записываются
в журнале выпуска без переноса счётчиков старых прогонов.

Устройство окружения Worker/Vinext: [vinext-runtime.md](docs/vinext-runtime.md).
Для работы через Sites используйте текущий доступный workflow публикации,
сохраняя существующий `project_id` и аудиторию сайта.
