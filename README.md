# Тропник

Карта России, маршруты для походов, поиск направлений и подготовка группы с гидом. Проект включает веб-приложение, Go API с PostgreSQL/PostGIS и нативное приложение Android.

## Веб-версия 0.4.30

Доработана отрисовка троп: карта показывает все исходные линии подходящих
под фильтр маршрутов, а выбранный маршрут выделяет поверх общего слоя.
Сохраняются режимы **«Рельеф» и «Спутник»** и собственный Canvas-движок.
Отдельная тяжёлая 3D-сцена не подключается.

- Все исходные отдельные части сохраняются без вымышленных соединений.
  При приближении подгружается точная геометрия видимой области; подготовка
  путей, память и очередь ограничены.
- Пять существующих карточек получили подтверждённую линию: два официальных
  GPX и три проверенных соответствия уже имеющимся трекам.
- Перепроверены все 326 отказов старого импорта по грубой маске. Пять троп
  восстановлены по неизменённым полным исходным границам.
- Для официальной береговой тропы «Чёрный ключ» исправлено сокрытие части
  линии исторической маской суши. Исключение требует точного совпадения
  координат с проверенным источником и не расширяет общую границу.
- Повтор загрузки и возвращение сети восстанавливают линию после ошибки.
  Просмотренные обзорный слой и подробные треки сохраняются с ограничением
  объёма кеша.
- Обзор и точные линии проверяются по SHA-256. Предзагрузка и выбранная
  карточка используют один версионированный запрос к геометрии.
- Кнопки карты сохраняют положение при нажатии и работе с клавиатуры.
  На телефоне история места временно скрывается, пока открыто меню слоёв,
  и возвращается после его закрытия.
- Большой слой троп растеризуется в отдельном worker. Результат применяется
  только к своему кадру; линии, маска и выделение выбранного маршрута
  сохраняются. Сохранённая аварийная карточка открывается без сети,
  в том числе при принудительном обходе HTTP-кэша.
- При поиске неподвижная карта без поворота и наклона повторно использует
  готовую подложку. Тропы и выбранный маршрут обновляются отдельно;
  повёрнутые и наклонённые виды сохраняют исходную отрисовку.

Веб-приложение: [orewn.github.io/tropnik](https://orewn.github.io/tropnik/). Каталог содержит **685 справочных маршрутов**: **624 с исходной геометрией** и **61 без подтверждённой линии**. Карточки представлены во всех **85 территориях существующего слоя карты**. Сохранены 15 туристических направлений; административные территории доступны отдельным списком.

На этапе национального дополнения каталог вырос с 306 до 680 карточек: добавлены 337 маршрутов с геометрией OpenStreetMap и 37 описаний по 47 первичным документам. В 0.4.30 восстановлены ещё пять ранее отклонённых карточек — всего стало 685; пять уже существующих карточек получили подтверждённые линии. Все прежние 277 активных геометрий и даты проверки старых карточек сохранены. Новые сегменты не соединяются вымышленными переходами; сведения о закрытии и неизвестных параметрах остаются явными. Покрытие всех разделов карты не означает наличие в каталоге каждой физической тропы или полевую проверку маршрутов.

Поиск использует подготовленные индексы текста и принадлежности к территориям. Карточки без линии приближают карту к реальным границам выбранной территории; регион корректно передаётся в паспорт похода. [Конструктор походов](https://orewn.github.io/tropnik/planner/) использует 624 карточки с геометрией и 2 004 возможных связи для проверки пользователем, сохраняет планы по дням и экспортирует JSON/GPX. Близость линий сама по себе не подтверждает возможность перехода.

Опубликованный Android `0.4.25-preview`, `versionCode 13`, содержит свой закреплённый каталог из 680 карточек и поддерживает отдельный выбор 15 направлений или 85 территорий. Индексы поиска и идентификаторов строятся один раз на ревизию каталога. Переключение списка обновляет точки карты без повторного чтения геометрии и движения камеры. Сценарий установленного universal APK проверяет нажатие на маркер новой территории, открытие и сохранение маршрута и возврат к списку.

## Собственная карта и ландшафт

[Исследование качества рендера, детализации и производительности](docs/rendering-research.md).

Камера, жесты, чтение MVT, картографическое оформление, подписи, маска покрытия
и композиция слоёв реализованы в собственном Canvas-движке `CustomMapEngine`.
Рабочая карта не загружает MapLibre, Leaflet или Protomaps. Браузер,
автономный просмотрщик и Android собираются из общего исходного движка;
отдельная сборка проверяет побайтовое совпадение подготовленных web/Android
ресурсов и отсутствие картографических SDK в графе модулей. Состав уже
опубликованного APK закреплён отдельным манифестом его выпуска.

Реальные высоты Terrarium используются для отмывки с несколькими направлениями
света, горизонталей и подписей высот. Подробные векторные участки
перерисовываются для текущего масштаба, сохраняя исходную геометрию.
В режиме «Спутник» подложкой служат снимки с обозначениями и маршрутом.
Увеличение масштаба не добавляет новых измерений и не повышает точность
исходной модели высот. Самостоятельный ландшафт Бзерпинского района остаётся
отдельным ресурсом автономного пакета, а не третьим режимом основной карты.

Декодирование тайлов и растеризация большого слоя троп выполняются вне UI-потока; растеризация троп использует отдельный worker и не занимает очередь рельефа. Очередь тайлов ограничена тремя запросами, очередь и кэш имеют пределы; общий пул не отдаёт свои единственные буферы через transfer. Нет постоянного цикла перерисовки в покое, скрытая карта приостанавливается. Спутник заменяет прежний слой после готовности обязательных участков отображаемого кадра. Эти свойства проверяются браузерными и Android-прогонами для конкретного commit; бюджет плавности оценивается отдельными браузерными измерениями. [Устройство и ограничения движка](docs/custom-map.md).

Результаты плавности относятся к конкретному браузерному профилю и commit.
Стабильные 60 FPS на любом устройстве не заявляются. Измерения прежнего
веб-выпуска `84f8206e`, его базы `3bd6e6bf` и отдельного эксперимента с подготовкой подписей приведены
в [журнале 0.4.29](docs/release-0.4.29.md). Исторические результаты
[0.4.28](docs/release-0.4.28.md) относятся к своему исходному commit.

В 0.4.25 очередь освобождает слот после каждого чтения основного тайла или соседних высот. Частично загруженный рельеф учитывается в общем лимите памяти; основные данные видимой карты получают свободные слоты между соседними тайлами. Потребители одного адреса разделяют исходные байты. Измеренные соседние высоты, разрешение источников и прежние ограничения загрузки сохранены. [Изменение и фактические проверки](docs/release-0.4.25.md).

## История предыдущих выпусков

## Что исправлено в 0.4.5

- **Подписи без наложений.** Четырёхсторонняя безопасная область дополнена фактическими прямоугольниками карточки историй, панели, сообщений, легенды, credits и органов управления. После загрузки шрифтов и изменения панелей выполняется повторный расчёт; при отсутствии допустимого места визуальная подпись скрывается, но доступное имя кнопки сохраняется.
- **Стабильный рельеф.** WebGL terrain включается только явным действием пользователя и не пересоздаётся после каждого zoom. В Canvas сохранены уже декодированные тайлы, увеличен буфер и введён раздельный порог входа/выхода из детального режима.
- **Точки и области.** Смешанный порядок координат центра маршрута исправляется по покрытию и выбранной территории. Клик по административной области оценивает все отрисованные кандидаты, а не случайный первый feature.
- **Интерфейс.** Финальный слой `interface-refresh.css` сводит поверхности, обводки, состояния кнопок, карточек, полей и карты к одной природной палитре.

## Что добавлено в 0.4.4

- **Маршруты из рассмотренных источников.** К прежним 277 карточкам добавлены 8 по материалу Яндекс Путешествий и 21 по подборке RussiaDiscovery с проверкой первичных страниц. Дополнительные источники также прикреплены к уже существующим карточкам. Даты публикации материала и редакторской проверки разделены. Известные ограничения посещения сохраняются, пока нет нового подтверждения открытия.
- **Поиск по сайту.** Единый индекс охватывает 306 маршрутов, 15 направлений, 13 историй о местах и 12 обычных страниц. Поиск учитывает русские формы слов, `ё/е`, транслитерацию, ошибочную раскладку и небольшие опечатки. Запросы вроде «Байкал до 15 км» используют только известные параметры; карточки с неизвестными значениями помечаются отдельно и могут быть исключены. Есть фильтр типа материала, страницы результатов и сохраняемый в URL запрос.
- **Карта.** Переключатели троп и границ управляют соответствующими слоями, общий список согласован с фильтрами карты. Пространственная проверка и кадрирование используют точное покрытие без изменения исходных линий. Улучшения проверены тестами; аппаратный FPS этим не измерялся.
- **Интерфейс.** Из экранов убраны номера сборок и служебные пояснения. Добавлены 12 авторских пиктограмм категорий. Категории описывают тему места, а не сложность, проходимость или допуск гида; события и группы автоматически не создаются.
- **История походов и аккаунт.** Реализованы приватная история завершённых участий, подтверждение email, восстановление пароля и закрытие аккаунта с отзывом доступа. Реальная работа этих возможностей требует развёрнутого API, базы и почты.
- **Android.** Встроенный каталог согласован с веб-экспортом: 306 справочных карточек, 15 регионов, 277 неизменённых геометрий и 29 карточек без линии. Поиск, сохранение карточки и дополнительные источники поддерживают отсутствие геометрии. Новые исходники не приписываются старому APK.
- **Telegram.** Готов импорт JSON-экспорта Telegram Desktop в закрытую очередь с отдельным ручным решением перед включением в каталог. История `poiskpohod` не получена: опубликовано **0 маршрутов из чата**. [Порядок импорта](docs/telegram-route-import.md).

## Данные и покрытие

Направления: Алтай, Краснодарский край, Карелия, Крым, Байкал, Камчатка, Воронежская область, Приморский край, Калининградская область, Красноярский край, Сахалин, Мурманская область, Адыгея, Карачаево-Черкесия и Кабардино-Балкария. Туристическое направление может объединять несколько административных территорий; его центр не является точкой старта маршрута.

Исторический слой карты содержит 85 элементов закреплённых источников: 83 RUS ADM1 и два ранее выбранных UKR ADM1. Это состав слоя отображения, **не утверждение о современном юридическом административном составе**. Исходные атрибуты, маска и происхождение сохранены. Для существующих линий территориальное членство считается геометрически; для новых карточек без линии используются рассмотренные `territoryIds`, без фиктивной точки или трека.

Веб-подсчёт включает только файлы из `sourceHashes`; повторные ссылки карточек учитываются один раз. Прежние 277 активных геометрий сохранены побайтно. Их наличие не подтверждает проходимость, длину полного официального маршрута или разрешение на посещение. Неизвестные время и сложность не заменяются выдуманными оценками. Расстояния новых карточек приводятся только при наличии в рассмотренном источнике; пояснение «в одну сторону» или другой способ измерения сохраняется.

Обзор России использует локальный пакет Natural Earth: **341 PNG**, исходные zoom 0–4. Это картографический рисунок, не подробная модель высот всей страны. Подробный автономный пакет ограничен Бзерпинским районом `[40.29, 43.64, 40.49, 43.82]`: **193 MVT, 21 DEM-тайл, производная сетка 513×513**. Подробная карта других районов получает высоты и картографические данные по сети. Более плотная сетка не повышает измерительную точность исходной съёмки. [Происхождение данных](docs/data-provenance.md), [описание обзорного рельефа](docs/overview-relief-provenance.md).

Используется Manrope с кириллицей и лицензией OFL. Лицензированные файлы Gotham Pro и материалы Quixel не предоставлены и не встроены. Авторские пиктограммы находятся в [компоненте категорий](web/components/EventCategoryIcon.tsx) и [SVG-листе](docs/design/event-categories.svg).

## Локальный веб и Pages

Для воспроизводимой сборки используются Node 24 и pnpm 11.25.0:

```sh
cd web
pnpm install --frozen-lockfile
pnpm dev
```

Команды `pnpm build` и `pnpm start` собирают и локально запускают Worker/Vinext
для Sites. `pnpm run build:next` и `pnpm run start:next` сохранены отдельно для
Next. Ни одна локальная команда запуска сама по себе не публикует сайт.

После правок общего движка или версии пакета из корня полного репозитория
обновите проверяемые производные ресурсы:

```sh
node tools/android-build/prepare-custom-map.mjs
node web/scripts/prepare-offline.mjs
node web/scripts/stamp-service-worker.mjs
node tools/android-build/prepare-custom-map.mjs --check
node web/scripts/verify-custom-map.mjs
node web/scripts/verify-map-shell.mjs
```

Включайте в commit оба каталога `custom-map` в web и Android, изменённый
service worker и все новые или удалённые файлы сборки. Web-only checkout
Sites проверяет соответствие общего runtime исходникам, но не генерирует
его вместо полного репозитория.

Из корня проекта статический сайт собирается так:

```sh
node tools/pages-preview/fetch-apk.mjs
node tools/pages-preview/build.mjs --base /tropnik/ --origin https://orewn.github.io
```

APK берётся из публичного release asset и проверяется по точным размеру и SHA256 из `web/public/downloads/android-manifest.json`. Сборка отклоняет отсутствующий или неверный файл. Workflow Pages собирает сайт из исходников при push в `main` и вручную, проверяет артефакт и выполняет проверку опубликованного адреса после deploy. Наличие workflow и локального ZIP не является доказательством успешного deploy. [Публикация Pages](docs/pages-publication.md).

Серверный код в Pages не входит, Go/PostGIS к статической сборке не подключён.
Ссылки `/account/action/` и `/search/` включены в маршрутизацию, но наличие
страницы аккаунта не подтверждает работу серверного действия. Токены действий
аккаунта передаются во fragment, не в query или metadata.

## Backend, история и жизненный цикл аккаунта

Для self-host задайте серверные `TROPA_API_URL` и `PUBLIC_ORIGIN`; origin Go API передаётся без `/api/v1`, BFF добавляет путь сам. Сессия браузера хранится в HttpOnly cookie. Секреты не должны попадать в `NEXT_PUBLIC_*`. Без конфигурации социальные действия возвращают `service_not_configured`; статический Pages не включает фиктивные ответы API.

Готовность проверяется через `/api/v1/health/ready`; текущая обязательная версия схемы — **5**. Миграция 004 добавляет историю, 005 — жизненный цикл аккаунта. Миграции выполняет владелец БД, работающий API использует ограниченную роль. Нужны стабильный `TROPA_AUTH_RATE_KEY`, отдельный proxy token и точные trusted peer CIDRs для настоящей цепочки ingress/BFF. [Настройка сервера](backend/README.md), [инфраструктура](infra/README.md).

История показывает только завершённые походы с подтверждённым участием текущего пользователя, сохраняет рассмотренную редакцию маршрута и использует устойчивую пагинацию. Обычные ответы и страницы маршрутов ограничены **1 МиБ** декодированного JSON; полная карточка с геометрией — **8 МиБ / максимум 100 000 вершин**. Android использует тот же отдельный бюджет полной карточки. [Адресный отчёт](backend/verification/history-budget-2026-11-06.json).

Подтверждение email действует **24 часа**, ссылка восстановления — **30 минут**. В БД хранятся хеши одноразовых токенов; смена пароля отзывает старые сеансы и ссылки. SMTP-очередь принимает максимум **36 заданий, включая активные**, использует **4 обработчика** и бюджет **20 секунд** на задание. Очередь находится в памяти и может потеряться при перезапуске; приём SMTP не равен доставке в почтовый ящик. Реальная почта в данном срезе не настроена; открытая регистрация закрыта без требуемого транспорта. [Проверка lifecycle](backend/verification/account-lifecycle-2026-11-06.json).

Закрытие аккаунта требует повторной проверки пароля и отсутствия активных обязательств; staff-аккаунт закрывается оператором. Профиль и учётные данные обезличиваются, доступ отзывается. Пользовательские тексты, участия, документы квалификации и аудит сохраняются: **полное стирание всех следов не заявляется**.

Для похода нужны минимум **четыре человека, включая назначенного гида**. Квалификация, открытый маршрут, дата, вместимость и присутствие проверяются при записи/старте. Набор интереса сам по себе не бронирует место. Для маршрута, требующего нескольких гидов, ограничение не ослабляется.

## Android и APK

Опубликован [Android 0.4.25-preview](https://github.com/orewn/tropnik/releases/tag/v0.4.25-preview), `versionCode 13`. [Universal APK](https://github.com/orewn/tropnik/releases/download/v0.4.25-preview/tropnik-preview.apk) — **67 858 685 байт**, с ARM64, ARMv7 и x86_64. Точные SHA-256, сертификат и исходный commit указаны в [download manifest](web/public/downloads/android-manifest.json); результаты сборки, JVM-тестов, сценариев установленного APK и проверки публичных файлов — в [журнале 0.4.25](docs/release-0.4.25.md).

Каталог включает 680 справочных карточек: 614 с исходной геометрией и 66 без линии, 15 туристических направлений и 85 территориальных разделов. Одна явно учебная карточка учитывается отдельно. Встроенный конструктор не заявляется: кнопки открывают полный веб-конструктор в обычном браузере после пояснения, где хранятся планы.

Preview использует development/debug-подпись. Сертификат этой сборки отличается от `0.4.24-preview`; совместимость обновления поверх прежней установки не подтверждена. Сценарии выполнены на эмуляторе API 35 / x86_64; физический ARM64 не проверен.

Для собственной сборки нужны JDK 17, Android SDK platform 36 / build-tools 36.0.0, Node и Python. После задания `ANDROID_HOME`:

```sh
python3 -m pip install -r tools/android-build/requirements.txt
bash tools/android-build/build.sh
```

Сборка выполняет генерацию, проверки ресурсов, JVM-тесты, подпись и проверку APK. Наличие instrumentation APK не означает выполнение теста на устройстве.

## Проверки качества

Из корня полного репозитория:

```sh
node --experimental-strip-types --test --test-concurrency=1 web/tests/*.test.mjs
node --test tools/pages-preview/tests/*.test.mjs
pnpm --dir web lint
node web/node_modules/typescript/bin/tsc -p web/pages-preview/tsconfig.json --noEmit
```

Проверки браузерной геометрии, переключения слоёв, загрузки, управления на
нескольких размерах экрана и плавности выполняются штатным
[Pages workflow](.github/workflows/pages.yml) на точной ревизии. Число тестов,
параметры браузера, build ID и результаты публикуются в датированном журнале
выпуска; исторические счётчики не выдаются за результаты нового кода.

Исторические команды, журналы и контрольные суммы:
[приёмка](docs/acceptance.md), [receipt 0.4.4](docs/verification/release-0.4.4-local.json).

Для каждого нового артефакта необходимы соответствующая приёмка и проверка его фактического commit; исторические отчёты не удостоверяют более поздний код. Публичные backend/SMTP, сквозной сценарий двух клиентов, аппаратные GPU/FPS и полевая проверка маршрутов не считаются выполненными по результатам браузерного CI. Их состояние отдельно указано в текущем журнале и runtime-аудите.
