# Тропник

Интерактивная карта России, справочные маршруты, подготовка походов с гидом и общение участников. Поставка включает веб-приложение, Go API с PostgreSQL/PostGIS, нативный Android-клиент и воспроизводимые локальные карты.

**Версия `0.4.2-preview`: веб и Android содержат шесть регионов, 277 справочных маршрутов и локальный обзорный рельеф России.** В Android также есть отдельная учебная карточка без геометрии маршрута. Все 277 исходных GeoJSON включены в APK; подробная автономная подложка и объёмная сцена остаются ограничены пилотным районом. Справочные записи не прошли полевую проверку и не получают статус готовых к навигации.

**Социальный backend реализован, но рабочий Go API/PostGIS пока не развёрнут и не подключён к preview.** Регистрация, группы, чат, отзывы и модерация требуют этого подключения. Карта, встроенный каталог и локальные ресурсы доступны независимо от него. Фактические проверки, APK и условия запуска описаны ниже и в [документе поставки](docs/final-delivery.md); подтверждение внешней публикации и хеш исходного архива выдаются отдельным release receipt.

### Офлайн: обзор и подробная карта

Обзорные тайлы России находятся в `web/public/maps/russia-relief` и отдельно в APK `assets/maps/russia-relief`. С metadata и атрибуцией это **344 файла / 1 759 234 байта**. Все native-файлы побайтно совпали с веб-пакетом, SHA256 PNG проверены по manifest. Веб service worker сохраняет полный обзор при успешной установке; в Android он уже входит в APK. Сетевой tile-server для этого слоя не требуется. [Отчёт подключения](docs/verification/native-russia-relief-source.md).

Подробная карта остаётся отдельным ограниченным пилотом: **193 MVT**, локальные блоки шрифта, **21 DEM-тайл** и сцена с производной сеткой **513×513**. Исходная сетка 129×129 и архив DEM сохранены. Более плотная производная сетка не повышает измерительную точность исходной съёмки. Наличие обзорного слоя на всей карте не означает наличия подробных троп, спутниковых снимков или цифровой модели высот по всей России.

Отдельно встроены **277 GeoJSON / 5 369 449 байт**: они побайтно совпадают с веб-источниками и доступны без API. Линия маршрута в каталоге не заменяет подробную подложку вокруг неё и не подтверждает проходимость. Учебная карточка «Как устроен маршрут» помечена как иллюстрация и не содержит геометрии.

При доступной сети Android может добавлять подробную карту OpenFreeMap и отмывку рельефа Mapterhorn начиная с zoom 5. Используются два явно разрешённых источника; Mapterhorn — Terrarium, 512 px, глобальный max zoom 12. В локальном режиме JSON стиля физически исключает оба сетевых источника и все 26 связанных слоёв; обзор, каталог, пилот и последняя RF-маска сохраняются. Это не скачанная подробная карта всей России. Атрибуция и адреса — в [manifest источников](android/app/src/main/assets/maps/online-sources.json); сетевое отображение на физическом устройстве не испытано.

В `0.4.1` также исправлены восстановление после terminal graphics failure и отмена загрузки после фиксации офлайн-пакета. Ошибка сцены снимает готовность и освобождает ресурсы; повтор открывает новую сессию. Отмена не удаляет уже опубликованный в локальной БД пакет. [Отчёт исправлений](docs/verification/android-recovery-0.4.1.md) отделяет проверенные сценарии от аппаратных испытаний.

### Правило группы

Минимум **четыре человека всего, включая назначенного гида**: базовый состав — гид и три туриста. Рассмотренная политика маршрута может требовать большего минимума или меньшей вместимости. В этой версии поддерживается один назначенный гид; маршрут, которому нужны несколько гидов, не открывается с ослабленным требованием.

Набор интереса без гида допустим как запрос с отдельным чатом. Датированный поход создаёт или принимает подходящий проверенный гид; туристы отдельно подтверждают участие в выбранные даты. Перед стартом сервер проверяет допуск гида, актуальную открытую версию маршрута, время, вместимость и фактическое присутствие. Офлайн-навигация остаётся доступной, но сохранённый состав группы не выдаёт разрешение на старт и не сообщает о последующей отмене. Подробнее: [архитектура](docs/architecture.md), [backend README](backend/README.md).

## Данные, достоверность и дизайн

Геометрия получена из OSM через Waymarked Trails и Geofabrik. Это общий первоисточник, а не два независимых полевых подтверждения. Закрытая база MAPS.ME, чужие аккаунты, отзывы и фотографии не копировались.

Из 278 исходных записей для 162 выполнено ограниченное интернет-исследование, 116 остаются `not_researched`. Сохранены 43 свидетельства с конкретной областью подтверждения. **Полная геометрия подтверждена авторитетным источником: 0; полевая проверка: 0; готовность навигации подтверждена: 0.** Эти показатели относятся к исходному набору, из которого одна запись исключена из RF-показа. Официальное описание, действующая ссылка и проверка геометрии — разные статусы. Источники и ограничения: [происхождение данных](docs/data-provenance.md), [матрица исследования](data/catalog/verification-coverage.json), [инструкция импортера](tools/import-data/README.md).

В перенесённом native-каталоге у 20 маршрутов есть дистанция из источника, у 19 — исходный текст длительности, у 40 — ограниченное официальное свидетельство с указанной областью подтверждения. Отсутствующие значения не превращены в расчётное время или вымышленную сложность. [Manifest каталога](android/app/src/main/assets/catalog-manifest.json) фиксирует состав и хеши геометрии.

Известное закрытие сохраняется до нового подтверждения; истечение срока перепроверки не делает маршрут открытым. Неизвестная сложность остаётся неизвестной. Бейджи и рейтинги API выводятся из событий участия и отзывов, а не из искусственно заданных оценок.

Интерфейс использует собственную систему пиктограмм и оформления. **Лицензионные файлы Gotham не предоставлены и не встроены.** В поставке используется Manrope с кириллицей и включённой лицензией OFL; получение и подключение Gotham остаётся отдельным действием владельца лицензии.

## Запуск веба

Нужны Node 24 и pnpm 11.25.0. Из корня проекта:

```bash
cd web
pnpm install --frozen-lockfile
pnpm exec next dev --hostname 127.0.0.1
```

Обычная production-сборка и запуск:

```bash
pnpm run build:next
pnpm run start:next
```

`build:next` / `start:next` относятся к стандартному Next, `build` / `start` — к отдельному Vinext/private-preview workflow. [Web README](web/README.md) также содержит инфраструктуру исходного preview-стартера.

Без серверной `TROPA_API_URL` работают справочные и локальные функции, а социальный BFF возвращает `503 service_not_configured`. Для настоящего подключения задайте origin Go API **без** `/api/v1`, например `http://127.0.0.1:8080` на том же хосте; BFF добавляет путь сам. Пользовательская сессия хранится в HttpOnly cookie. Строка БД и серверные секреты не должны попадать в `NEXT_PUBLIC_*`.

Наличие URL не считается подключением. Веб и Android проверяют `/api/v1/health/ready`; Go требует актуальную схему **3**. Веб возвращает `connected:true` только по HTTP 200 с корректными `data.status:"ready"`, `meta.mode:"production"` и без `error`. Готовность БД в момент проверки не гарантирует последующий успех записи. [Аудит связей](docs/connection-audit.md).

Перед публичной сборкой задайте реальный `NEXT_PUBLIC_SITE_URL`. По умолчанию `TROPA_PUBLIC_INDEXING=false`; публичная индексация требует рассмотренного контента и соответствующей build/runtime-конфигурации. `noindex` не заменяет контроль доступа.

## Сервер, база и авторизация

[Инструкция self-host](infra/README.md) описывает переменные, миграции, runtime-права и HTTPS ingress. Для Docker нужен обычный x86-64 Linux-хост с Docker Compose. В доступной среде production-контейнеры не запускались.

```bash
cd infra
cp .env.example .env
# Заполните DB-пароли, стабильный auth HMAC key, свой HTTPS origin.
# Для Caddy/BFF задайте отдельный proxy token и точные trusted peer CIDRs.
docker compose -f compose.yaml -f compose.web.yaml --env-file .env up --build -d
```

Миграция **003** добавляет общие PostgreSQL-бюджеты: 20 попыток регистрации/входа по IP и десять попыток входа по нормализованному аккаунту за 60 секунд. В таблице только HMAC-идентификаторы, счётчики и время; plaintext email/IP не сохраняются. Отказы фиксируются, старые строки очищаются ограниченными партиями. Сбой БД закрывает попытку с `503`.

Обязателен стабильный `TROPA_AUTH_RATE_KEY`, общий для API-реплик. Для точного учёта посетителей за BFF нужны **другой** `TROPA_PROXY_TOKEN` на Caddy/Next/Go и `TRUSTED_PROXY_CIDRS` на Go. Прокси заменяет заголовки; Go проверяет токен и фактического сетевого соседа. Произвольный forwarded header не принимается. Managed Sites не настраивает такую цепочку автоматически. [Аудит auth/proxy](docs/auth-proxy-audit-2026-11-06.md).

База не публикует порт. Миграции выполняет владелец, API использует ограниченную роль. Гид, администратор и опубликованные маршруты автоматически не создаются. [Операторский CLI](backend/README.md) фиксирует результат реальной проверки квалификаций и рассмотрения маршрута; сама команда не проверяет документы или местность.

## Архив и self-host загрузка APK

Предусмотрены два разных архива: полный проект для разработки/self-host и скомпилированный статический сайт для Pages. **`tropnik-test.zip` версии 0.4.2 — 37 211 651 байт**, SHA256 `5b69ca387c9b72d67e33f2e00d3e52fa0fc881fb1ebc2126ea607853160df4e7`. Он содержит 297 страниц, включая 277 справочных маршрутов, и проверенную ARM64-загрузку 0.4.2. [Отчёт локальной сборки](docs/verification/pages-final-0.4.2.json) фиксирует маршрутизацию, ресурсы, HTTP-проверки и содержимое ZIP.

**Действующего GitHub Pages URL эта поставка не заявляет:** для текущего приватного репозитория доступный план требует смены плана или публичности. Скомпилированный ZIP можно разместить отдельно. Изменение видимости репозитория автоматически не выполняется.

APK передаются **отдельно от ZIP исходников**. Source ZIP содержит проект и необходимые runtime-ресурсы; SDK, toolchains, кэши, `node_modules`, build outputs, ключи и готовые APK в него не включаются. Итоговый inventory определяет точный состав архива. Публикация обновлённого ZIP и GitHub должна подтверждаться отдельным release receipt.

Для кнопки загрузки на собственном сайте положите переданный финальный ARM64 APK в `web/public/downloads/tropnik-arm64-preview.apk` **до сборки веба**. После локальной Android-сборки:

```bash
mkdir -p web/public/downloads
cp android/dist/tropnik-arm64-preview.apk web/public/downloads/tropnik-arm64-preview.apk
```

Сверьте SHA256 с таблицей выше и сохраните актуальный download manifest. Наличие файла в локальном `public/` не является доказательством успешной новой веб-публикации.

Native PostgreSQL integration-бинарник скомпилирован и отказывает без `TEST_DATABASE_URL`; многосеансовые транзакции, реальная runtime-роль по сети, контейнеры и live web/Android → API → PostGIS ещё не проверены. PGlite использует один SQL-сеанс и экспериментальный PostGIS; `SET ROLE` подтверждает SQL grants, а не SCRAM/TLS. Контактная верификация, восстановление/удаление аккаунта, штатная модерация, резервное восстановление, эксплуатационные процессы и device/field-проверка остаются условиями публичного запуска. Полный перечень — в [итоговой поставке](docs/final-delivery.md) и [критериях приёмки](docs/acceptance.md).
