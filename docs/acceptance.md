# Приёмка Тропника: реализация и проверка

Срез: **6 ноября 2026 года**. Этот документ разделяет наличие кода, успешную сборку, выполненный тест и эксплуатационную проверку. Неподключённый социальный backend preview не считается работающим публичным сервисом. Все критерии ниже относятся к проверяемому поведению, а не к условному проценту готовности.

Объединённые Android 0.4.0 и обычный Next production build собраны. Пройдены 101 веб-тест, три integration-проверки каталога/маски и ограниченная браузерная QA Canvas-карты, клавиатурного перехода к terrain-сцене и мобильной компоновки. Финальная Sites/Vinext-сборка и owner-private публикация успешны. Source snapshot формируется из зафиксированного дерева с отдельным inventory. См. [отчёт объединения](merge-release-2026-11-06.md).

## 2. Проверки, которые не объявлены пройденными

Фактическая связь компонентов, production env revision 0 и условия запуска сервера описаны в [аудите подключений](connection-audit.md). Успешная публикация фронтенда не развёртывает Go/PostGIS автоматически.

- Реальное выполнение миграций 001/002, PostGIS-функций, ограничений, прав runtime-роли и конкурентных транзакций. В среде подготовки не было работающего PostgreSQL/Docker; попытка обычной установки не могла сменить системного пользователя, обход привилегий не применялся.
- Полный сценарий управления указателем: `Input.dispatchMouseEvent` сталкивался с таймаутом. Клавиатурный сценарий и accessibility tree повторно работали; read-only review не выявил очевидного бесконечного RAF/runaway preload, но причина таймаута не установлена.
- GPU WebGL2-рендеринг и аппаратный FPS: QA-браузер не предоставляет WebGL2. Ограниченная Canvas/UI-проверка пройдена, но она не охватывает все браузеры, жесты и реальные мобильные устройства.
- Сквозной сценарий с развёрнутой базой: два клиента, регистрация, публикация рассмотренного маршрута, реальный допуск гида, набор, переписка, старт, завершение и отзывы.
- Docker image build/start, production ingress, доверенная передача IP, восстановление резервной копии, нагрузка, внешняя проверка безопасности и SBOM/vulnerability scan.
- Выполнение Android Compose/instrumentation на эмуляторе или телефоне; аппаратная UI-проверка, масштабирование шрифта, TalkBack, системные разрешения, реальный GPS и расход батареи.
- Настоящее открытие карты и 3D сцены в airplane mode на Android, обновление/повреждение пакета на физическом устройстве и поведение при нехватке диска.
- Production release signing, обновление существующей установки с release-ключом, публикация в магазин и запуск GitHub Actions workflow.
- Полевая/геометрическая проверка маршрутов и текущая готовность навигации. У исходных 278 отношений эти показатели равны нулю.

## 3. Обязательный прогон с настоящей БД

На Docker-хосте из корня проекта:

```bash
bash infra/run-integration.sh
```

Скрипт создаёт отдельный временный стек и тестовую БД; не использует production volume. Альтернатива: `TEST_DATABASE_URL` указывает на изолированную БД с именем, заканчивающимся `_test`, затем `go test -race -tags=integration ./internal/store` из `backend/`. Отсутствие такой БД должно прерывать gate, а не превращаться в зелёный «пропуск».

| Сценарий | Ожидаемый результат |
|---|---|
| Одновременные заявки на последнее место | Вместимость не превышена; один и тот же человек/гид не посчитан повторно |
| Повтор после потерянного ответа | Тот же ключ и payload возвращают прежний результат; изменённый payload конфликтует |
| Участник ушёл до старта, стало трое | `ready` снят; старт невозможен |
| Гид ушёл, допуск отозван или истёк | Новый старт невозможен; фактическое происшествие текущего выхода можно зафиксировать |
| Маршрут закрыт или версия заменена | Старое состояние клиента не даёт право присоединиться/стартовать |
| Четыре записи без четырёх присутствующих | Старт отклонён; численность подписавшихся не подменяет явку |
| Чужой приватный чат, roster или жалоба | Доступ отклонён; ответ не выдаёт тело чужого сообщения/контакты |
| Неподтверждённый гид пытается создать выход | Отказ; выбор `guide` при регистрации не является допуском |
| Завершение и отзыв | Один отзыв на цель/выход; собственный гид и неявившийся участник не могут его оставить |
| Отозванная staff-роль | Старый токен не открывает очередь и не позволяет принять решение |
| Жалоба на сотрудника | Только независимый допустимый уровень видит содержание; субъект и автор жалобы не решают дело |
| Апелляция | Субъект, первоначальный заявитель и первоначальный модератор исключены из staff review |
| Два действующих скрытия, одно отменено | Материал остаётся скрытым по второму основанию |
| Ограничение публикаций | Новые сообщения/отзывы/наборы блокируются; жалоба, апелляция и incident handling доступны |
| Параллельный антиспам в разных каналах | Общий и поканальный бюджеты сохраняются; повторы принятого `clientId` не съедают новый лимит |
| Скрытый message replay | Возвращается прежний ID с пустым телом, а не утечка сохранённого текста |
| Кабинет/награда/уведомление | Реальное событие с evidence ID; отсутствие события не рисует награду; чужое уведомление не читается |
| Офлайн-наблюдение со старой версией | Явный конфликт; даже успешный ack содержит `serverAuthorized:false` |

Эти сценарии реализованы в интеграционном тестовом наборе; наличие строки в таблице не означает, что он уже прошёл на PostgreSQL.

## 4. Приёмка веба и APK на развёрнутом стенде

Перед выполнением зафиксировать URL/версию API, схему БД, source manifest и SHA256 APK. Создать контролируемые тестовые аккаунты, рассмотренный тестовый маршрут и квалификацию без представления их публике как настоящей группы.

1. Веб и Android видят одинаковые данные. Браузер не получает Bearer в JSON/localStorage; Android не отправляет его не тому origin. Смена сервиса разделяет локальный кэш.
2. Проверить регистрирующегося туриста и заявку гида, ошибочный пароль, истёкший сеанс, возврат сети и выход при неопределённом ответе. UI сообщает подтверждённое локальное состояние и не заявляет неподтверждённый серверный отзыв.
3. Создать запрос на набор, вступить в чат, принять его проверенным гидом. Участник запроса вступает в датированный поход явно; интерес не бронирует место автоматически.
4. Создать выход с правилом «четыре всего включая гида», затем повторить случаи underflow, отзыва допуска, новой версии и отметок присутствия. Быстрые повторные клики/ответы не подменяют новую группу или другой аккаунт.
5. Отправить сообщение с потерей ответа, обновить экран и повторить. Должен остаться один серверный message. Непринятое/офлайн сообщение не называется доставленным.
6. Рассмотреть жалобу, скрыть материал, обновить свежий блок переписки на обоих клиентах. Текст исчезает из активного снимка; отключённый старый кэш обозначается устаревшим. Проверить апелляцию независимым сотрудником.
7. Сохранить пакет до потери сети, перезапустить Android в airplane mode, открыть карту/сцену и явно выйти за bbox. Покрытие не должно обещать подробную карту за его пределами. Повреждённый или неполный пакет не получает статус готового.
8. Проверить отказ разрешения геолокации, приблизительную позицию, отсутствие GPS fix, крупный шрифт, TalkBack, landscape и нехватку памяти. Ошибка социальной части не должна отнимать сохранённую карту.
9. Проверить SSR/metadata, canonical на реальном домене, private/noindex страницы, sitemap только опубликованного контента и отличие API outage от отсутствующего маршрута.
10. Проверить загрузку отдельно переданного APK по кнопке сайта и сравнить SHA256. Исходный ZIP не содержит дубликата APK; его размещение является отдельным deployment-шагом.

## 5. Границы публичного запуска

Оператору нужны контактная верификация, восстановление и удаление аккаунта, staff MFA/SSO, сотрудники для модерации и независимых апелляций, сроки хранения и удаления, процесс рассмотрения квалификаций/разрешений, проверенный backup restore и настроенные лимиты фактической инфраструктуры. Технический CLI не устанавливает юридическое соответствие, а выбор региона хостинга сам по себе не доказывает соблюдение всех требований.

Текущий backend сохраняет уведомления, но не доставляет email/push. Не реализованы платежи, актуальная погода, спутниковый SOS, гарантированная доставка спасателям, автоматическая подача в МЧС, проверка сговора, полноценный маршрутизатор или офлайн перепрокладка. Протоколы и интерфейсы не должны обещать эти возможности.

Содержание исследований, маршрутные ограничения и правовые выводы имеют даты и источники в [research-rf-seo](research-rf-seo.md) и [data-provenance](data-provenance.md); перед реальной эксплуатацией их нужно актуализировать. Полевая проверка — отдельная работа ответственных специалистов, не результат компиляции карты.
