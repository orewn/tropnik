# Тропник: рабочая память проекта

Обновлено 9 ноября 2026 года. Стабилизация карты 0.4.18 после жалоб на задержки и потерянные нажатия опубликована и прошла приёмку. Объект работы — `orewn/tropnik`, публичный GitHub Pages, соответствующий Android APK и существующий закрытый Site. Общая формулировка про «ферму» не меняет этот объект на другой проект.

## Решения, которые нужно сохранять

- Карточки и линии на карте используют один отфильтрованный набор маршрутов. Составной поход рассчитывается по настоящим сегментам; неподтверждённый переход остаётся разрывом, а не придуманной прямой.
- Исходная геометрия, source digest, проверки fingerprint, происхождение и ограничения сохраняются. Оптимизация не сокращает GPX и не меняет дистанцию. 277 геометрий из 306 карточек; 29 карточек без линии не участвуют в конструкторе.
- Карту нужно принимать по реальным нажатиям: направление → точка маршрута → обратно → другое направление; отдельно ПК и телефон, Canvas и WebGL. Проверка наличия обработчика или зелёные source-regex tests этого не доказывают.
- Обработчик WebGL выбирает один результат с приоритетом тропы. Canvas территорий и точек общий: отдельный прозрачный Canvas поверх маркеров возвращать нельзя. Зона попадания точки — 44 CSS px при прежнем визуальном размере.
- Панорамирование пользователя прекращает автоматическое кадрирование. Поздняя геолокация не должна перебивать новую тропу, жест или более свежий запрос. Смена размеров и завершение анимации панели учитываются отдельно.
- На узком экране повторное нажатие группы направлений должно увеличивать масштаб. После возврата к России рамка пересчитывается после закрытия панели.
- Возраст спутникового слоя скрыт в элементах выбора карты. Сведения об источнике и лицензии остаются в источниках и атрибуции.
- Нельзя скрывать дату проверки и статус доступа тропы, выдавать справочную геометрию за разрешённый путь, придумывать гидов, отзывы, участников или подтверждение МЧС.
- Gotham Pro не подключается без предоставленных лицензированных файлов. Существующая кириллическая Manrope и индивидуальные иконки остаются рабочей системой.

## Конфигурация и типы

`web/lib/map-config.ts` — общие бюджеты ресурсов, области историй, hit radius, масштабы и параметры геолокации двух карт. `web/lib/map-types.ts` — координаты `[longitude, latitude]`, границы и входные параметры карт. `web/lib/route-geometry.ts` — проверяемая граница статического GeoJSON/API envelope. Публичные API контракты остаются в `contracts/` и `web/lib/contract.ts`; настройки SMTP, сервера и мобильной сборки не подменяются клиентскими константами.

Пакеты фиксируются lockfile и единственной конфигурацией pnpm. Обновления должны проходить frozen install, типы, регрессии и обе рабочие сборки. Production dependency audit и audit инструментов сборки сообщаются отдельно.

## Рабочий кандидат 0.4.19 — ещё не опубликован

После скриншота Brave исправляются жесты панели и оформление карты при приближении. `sheet-gesture.ts` управляет только ручкой и свёрнутым блоком: максимум один transform за кадр, без React и чтения layout на каждом движении. Tap/клавиатура, cancel/lost capture, второй указатель, resize и поздние callbacks должны оставаться защищены отдельными поведенческими проверками. Список сохраняет нативную прокрутку.

В панели отключены `content-visibility:auto` и приблизительная высота карточек: наблюдались 132 px вместо настоящих 262–338 px и скачок `scrollHeight`. Сохранена выдача по 12 карточек. Нельзя возвращать перерасчёт карты на каждом изменении inline-стиля панели: реальные размеры обслуживает `ResizeObserver`, завершение движения — `transitionend` или единичный `tropnik:sheet-settled` при мгновенном изменении.

Быстрые «+»/«−» должны менять накопленную цель `MapZoomButtons`, а не промежуточный масштаб анимирующего SDK. Подтверждённый прежний сбой: четыре «+» от 14 давали 16,25. После исправления настоящие нажатия дали 17, четыре «−» вернули 14; шаг Leaflet 0,75 сохранён. Держать только одну цель и один RAF; ручная навигация отменяет старую очередь. Отдельные 16 регрессий входят в общий web suite.

Отметки А/Б на карте обозначают только края одной исходной линии; они не подтверждают старт/финиш похода. Составным линиям порядок не придумывать. Карту необходимо принимать реальными touch-жестами и проходом по масштабам до 18 на Canvas и WebGL; снимки ключевых масштабов требуют визуального просмотра. Недоступные спутниковые снимки или 3D записывать как fallback/error.

В 3D нельзя оставлять поверх сцены уведомления плоской карты и блок историй. На узком экране все шесть кнопок, включая сброс, должны оставаться доступны с областью 44 × 44 px. `observeTerrainViewport` учитывает фактические видимые HUD и конечное положение панели; открытая панель скрывает второстепенные заголовок/подпись. Не возвращать постоянный пересчёт камеры по изменению `style`.

Опубликованную сетку маски покрытия нельзя повторно упрощать независимо по ячейкам в Leaflet: это создаёт щель на общем крае. Для маски сохранять `smoothFactor:0` и viewport clipping; это не повод менять исходную геометрию маршрутов. `maskViewportCulling` пропускает проекцию ячеек за буфером экрана, возвращая их при pan без zoom; неизвестный viewport должен сохранять обычную проекцию. Collision box подписей Canvas должен включать светлый ореол. На близком zoom сохранённый обзор обозначать как «Обзор без деталей» в существующей плашке, не обещать отсутствующую детальную подложку и не затирать сообщение об ошибке.

Текущий локальный срез: **430/430 web tests, 26/26 Pages tooling tests, оба TypeScript-прогона и ESLint — PASS**. В lint исправлен только тестовый alias `this`; восемь проверок viewport повторно прошли. Фабрика `createLeafletCanvas` предотвращает потерю RAF ID при синхронной перерисовке установленного Leaflet; защита ограничена нашими экземплярами, повторное добавление рендера работает. **Браузерный CI, публичная проверка и публикация 0.4.19 пока PENDING; физический Android/Brave не проверен.** Итоговые commits и receipts должны появиться в `docs/release-0.4.19.md`. До этого последним подтверждённым опубликованным выпуском остаётся 0.4.18. Изменения только документации не должны заново запускать публикацию; runtime/workflow по-прежнему требуют полного CI.

Не объявлять production-сервисом функции, для которых не настроены backend/PostGIS, SMTP или рабочие операторские процедуры. Не заявлять проверку физического ARM64-телефона по результату эмулятора. Development-подпись APK и браузерный характер конструктора в Android должны быть явно указаны.
