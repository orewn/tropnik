# Тропник: рабочая память проекта

Обновлено 9 ноября 2026 года. Текущая задача — стабилизация карты и релиза 0.4.18 после жалоб на задержки и потерянные нажатия. Объект работы — `orewn/tropnik`, публичный GitHub Pages, соответствующий Android APK и существующий закрытый Site. Общая формулировка про «ферму» не меняет этот объект на другой проект.

## Решения, которые нужно сохранять

- Карточки и линии на карте используют один отфильтрованный набор маршрутов. Составной поход рассчитывается по настоящим сегментам; неподтверждённый переход остаётся разрывом, а не придуманной прямой.
- Исходная геометрия, source digest, проверки fingerprint, происхождение и ограничения сохраняются. Оптимизация не сокращает GPX и не меняет дистанцию. 277 геометрий из 306 карточек; 29 карточек без линии не участвуют в конструкторе.
- Карту нужно принимать по реальным нажатиям: направление → точка маршрута → обратно → другое направление; отдельно ПК и телефон, Canvas и WebGL. Проверка наличия обработчика или зелёные source-regex tests этого не доказывают.
- Обработчик WebGL выбирает один результат с приоритетом тропы. Canvas территорий и точек общий: отдельный прозрачный Canvas поверх маркеров возвращать нельзя. Зона попадания точки — 44 CSS px при прежнем визуальном размере.
- Панорамирование пользователя прекращает автоматическое кадрирование. Поздняя геолокация не должна перебивать новую тропу, жест или более свежий запрос. Смена размеров и завершение анимации панели учитываются отдельно.
- На узком экране повторное нажатие группы направлений должно увеличивать масштаб. После возврата к России рамка пересчитывается после закрытия панели.
- Возраст спутникового слоя скрыт в элементах выбора карты. Сведения об источнике и лицензии остаются в источниках и атрибуции.
- Нельзя скрывать дату проверки и статус доступа тропы, выдавать справочную геометрию за разрешённый путь, придумывать гидов, отзывы, участников или подтверждение МЧС.
- Gotham Pro не подключается без предоставленных лицензированных файлов. Существующая кириллическая Manrope и индивидуальные иконки остаются рабочей системой.

## Конфигурация и типы

`web/lib/map-config.ts` — общие бюджеты ресурсов, области историй, hit radius, масштабы и параметры геолокации двух карт. `web/lib/map-types.ts` — координаты `[longitude, latitude]`, границы и входные параметры карт. `web/lib/route-geometry.ts` — проверяемая граница статического GeoJSON/API envelope. Публичные API контракты остаются в `contracts/` и `web/lib/contract.ts`; настройки SMTP, сервера и мобильной сборки не подменяются клиентскими константами.

Пакеты фиксируются lockfile и единственной конфигурацией pnpm. Обновления должны проходить frozen install, типы, регрессии и обе рабочие сборки. Production dependency audit и audit инструментов сборки сообщаются отдельно.

## Релиз и доказательства

Нативные изменения 0.4.18 отправлены в `c4498b496d4d6963c94023e8425b6e845eedc7db`. Это source commit, а не само по себе доказательство успешного APK. Выпуск должен пройти JVM, инструментальные проверки установленного APK и pixel gate 3D-сцены. Нельзя перезаписывать опубликованные версии APK: новый код — новый immutable tag, manifest и SHA-256.

Итог публикации, точные commits, workflow runs и контрольные суммы фиксируются в `docs/release-0.4.18.md` после получения результатов. Аудит причин и незавершённых интеграций — `docs/runtime-audit-2026-11-09.md`. Предыдущий релизный журнал не является подтверждением нового кода.

Не объявлять production-сервисом функции, для которых не настроены backend/PostGIS, SMTP или рабочие операторские процедуры. Не заявлять проверку физического ARM64-телефона по результату эмулятора. Development-подпись APK и браузерный характер конструктора в Android должны быть явно указаны.
