**Статус: frozen merged 0.4.0; Android, Next и Sites/Vinext собраны, приватная веб-публикация успешна.** Пройдены 101 веб-тест и три проверки каталога/маски. В браузере подтверждены ограниченный Canvas/UI-сценарий, клавиатурное открытие региона/terrain и мобильный обзор; автоматизация указателя сталкивалась с таймаутом. Итоговый source snapshot формируется из этого дерева с inventory и повторной сверкой ZIP. Параллельный источник не перезаписывался.

## Что подтверждено для рельефа

В основном дереве выполнены проверка и новое построение через `tools/map-package/refine_terrain.py`. [Свежий отчёт](verification/terrain-refinement.json) относится к этому дереву, а не просто скопированному заявлению параллельной сборки.

- Итоговый `web/public/terrain/terrain-grid.json`: **513×513, 263 169 высот**, 1 823 647 байт, SHA256 `ce2d0be1f749dae6b24b2a949b878a66fe84746ed8d979312a1c8afa4ee06a55`.
- Preview: **129×129**, 117 031 байт, SHA256 `33d73d4f1a88a2c226845ed9c382b523b88638b1e99b0fd199384369ea31af9d`; сохранён исходный preview.
- Проверены 48 записей manifest; для плотной сетки используются 12 архивированных PNG-тайлов zoom 12. Архивное дерево из 49 файлов не изменено.
- Перенесён общий WebGL2-рендерер. Он предназначен для веб-страницы и встроенного локального HTML в Android WebView; MapLibre Native сохраняет свою роль нативной карты и не объявляется движком этой объёмной сетки.

Более плотное отображение получается повторным сэмплированием существующих DEM-данных. Оно не означает новую съёмку, повышенную измерительную точность или наблюдаемую растительность. Процедурный материал — оформление, а не подтверждённая классификация покрытия земли. Статусы `fieldVerified:false` и `navigationReady:false` сохраняются. Текущие ограничения маршрута и сведения об источниках должны оставаться видимыми независимо от качества изображения.

## Android: сохранение поведения

API/readiness клиент, состояния проверки сервиса и социальные функции не заменяются более ранней параллельной версией. В сцену переносится один удерживаемый WebView: подготовка происходит за карточкой, открытие и возврат используют тот же экземпляр, а «Назад» возвращает к карточке маршрута.

Проведён ограниченный read-only обзор `TropaApp` и `LocalLandscapeScene`: в скрытом состоянии закрыты focus/accessibility и действия сцены; контейнер перекрыт непрозрачной карточкой; предусмотрены pause/resume, очистка callback/timer, обработка потери renderer и освобождение WebView. Найденный крайний случай смены lifecycle owner исправлен владельцем Android добавлением lifecycle в ключ удерживаемого viewer. Это проверка исходников, **не успешный запуск на телефоне**.

В объединённой сборке выполнены **22 JVM-теста**: восемь API contract/readiness, три адреса API, четыре landscape-assets, три moderation, три offline integrity и один RF geometry test с 22 точечными случаями. Ошибок, провалов и пропусков нет. Дополнительно прошли 10 Python-тестов подготовки assets и четыре Node-теста bootstrap. Это числа из фактических отчётов текущего запуска, а не сумма старых результатов. Instrumentation APK с четырьмя сценариями заново скомпилирован, но не выполнен.

Файлы сверены независимо по размеру и SHA256; [сводный Android отчёт](verification/android-final-packages.json) и [unit results](verification/android-unit-tests.json) включены в исходники:

## География и текущая проверка интерфейса

Маска использует явно выбранные исторические ADM1 источники с сохранёнными ISO-метками, лицензиями и raw GeoJSON. Она задаёт область интерфейса, не текущую юридическую границу. `osm-relation-14407325` целиком вне охвата и исключён из RF-выборки; исходный объект не удалён из аудита. [Проверка покрытия](../data/boundaries/catalog-mask-coverage.json) охватывает все 223 073 исходные вершины; число ошибочно удалённых упрощением покрытых вершин — 0.

В React fallback и standalone offline добавлены общий расчёт полного охвата, minZoom по viewport, ограничения центра, point-in-polygon для событий/GPS и верхняя неинтерактивная маска. Leaflet использует Canvas и tile size 256; подписи проверенных маркеров находятся выше маски, линии ниже. Офлайн MapLibre использует каноническую маску и `transformConstrain`. Карта скрывается до загрузки географии. Вместо большой постоянной строки источников установлен раскрываемый доступный блок; начальная OSM-атрибуция видна восемь секунд, полные данные сохраняются по кнопке.

Синтаксис offline JS/SW, TypeScript-check fallback и layout regression test пройдены. Проверены 33 пути shell v7 и используемые HTML IDs. В начальном Canvas-обзоре используются локальные границы; автоматическая загрузка подробной тайловой подложки начинается с zoom 4. При возврате ниже zoom 4 слой освобождается, а незавершённая установка инвалидируется; эта последняя правка прошла повторный прогон 101 теста и финальный Sites build/deploy. В повторной QA клавиатура Enter открывала Краснодарское направление с 98 маршрутами и terrain-сцену; accessibility tree возвращал полное содержимое. На скриншоте видно отображённый объёмный рельеф. Мобильный экран 390×844 показывает шесть региональных подписей, нейтральный фон, свёрнутую панель и отсутствие наложения story/атрибуции. При этом `Input.dispatchMouseEvent` сталкивался с таймаутом; полного pointer-сценария не подтверждено. Read-only review renderer не выявил очевидного бесконечного RAF или runaway preload, но не установил причину таймаута. [Отчёт QA](verification/browser-merged-qa.json) не подтверждает GPU WebGL2, FPS или работу на телефоне.

## Подключения и публикация

Go API/PostGIS **не развёрнуты**. Последняя подтверждённая production-конфигурация Sites — revision 0 с пустым списком переменных; `TROPA_API_URL` не задан. Строгая readiness-проверка сохраняется и не должна показывать зелёный статус от одного наличия URL. Объединение карты не создаёт регистрацию, живые чаты или реальные группы без сервера.

Окончательная owner-private публикация merged 0.4.0 успешна: commit `45cd0bc39423ebee7109cac92bf18f09a87720b3`, deployment `appgdep_6aed8957b0908191bf833c6fdf54abd5`, version `appgprj_6aed4db0a81881919cc3840d28cfad27~appgver_a08dcd2bf8fc81918b852ca704f5f07d`. Сохранены прежний URL и приватная аудитория владельца. [Машинный отчёт](verification/merged-site-publication.json) фиксирует статус и env revision 0; [connection-audit](connection-audit.md) описывает ограничения доступа и неподключённый API.

Private GitHub `orewn/tropnik` создан, но по последней подтверждённой проверке его `main` содержит только README. Черновик релиза не означает, что blobs, полный source tree или release assets уже загружены. Новое состояние GitHub можно указывать только после фактической записи и последующего чтения результата.

Для self-host APK по-прежнему передаётся отдельно: перед web build финальный ARM64-файл необходимо поместить в `web/public/downloads/tropnik-arm64-preview.apk` и согласовать download manifest с его фактическим размером/SHA. В source ZIP APK не дублируется.

## Состав передачи и оставшиеся эксплуатационные работы

Frozen generated assets возвращены в основное дерево до упаковки. Офлайн-пакет содержит **252 ресурса** (193 MVT и 21 DEM): **6 861 440 байт ресурсов + 147 281 байт manifest = 7 008 721 байт**. Все размеры/SHA сверены, ошибок нет. Две веб-копии terrain HTML идентичны: **1 958 485 байт**, SHA256 `a0807ff332a5caf72cca79ad3850ee8f6095f0175df2be5940a9008e203cce88`. [Финальная сверка](verification/web-offline-final.json) включает shell, конкретные локальные ссылки стилей и APK download manifest.

Android CI workflow синхронизирован с закреплённым шаблоном; запуск GitHub Actions отдельно от наличия YAML и пока не заявлен как выполненный. APK уже включён в опубликованный Site, а source ZIP содержит только импортируемый download manifest, без дубликата APK. Для самостоятельного хостинга файл APK размещается отдельным шагом.

Упаковщик сохраняет полный общий renderer, 513×513 grid и архивный preview, viewport helpers, Kotlin/Go/веб-код, документы, исходные boundary RUS/UKR и лицензии. Source-профиль также сохраняет большой OSM PBF и raw ways; GitHub-профиль исключает только эти два audit-файла. `SOURCE-INVENTORY.json` содержит все выбранные размеры/SHA; сопровождающий `package-result.json` фиксирует размер/SHA самого ZIP и результат повторной сверки. Собственный ZIP-хеш не встраивается внутрь этого же архива.

После заморозки исходников упаковка не меняет приложение. Публикация полного GitHub tree и release assets остаётся отдельным действием владельца; существующий draft не считается завершённой публикацией.

Остаются эксплуатационные работы: настоящий API/PostGIS, права БД и конкуренция транзакций, квалификации гидов, подготовка операторов, восстановление резервной копии, проверка Android на устройстве и полевые проверки маршрутов. Ни сборки, ни целостность поставки их не заменяют.
