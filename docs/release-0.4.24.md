# Тропник 0.4.24-preview: публикация

11 ноября 2026 года. **Android 0.4.24-preview опубликован и проверен по публичным байтам.** Обновление сайта с точным universal APK проходит отдельный окончательный цикл GitHub Pages; его завершение пока не заявляется.

Пока завершалась эта публикация, в основную ветку отдельно влит следующий [выпуск 0.4.25 с изменённой очередью источников](https://github.com/orewn/tropnik/pull/18). Этот журнал сохраняет точные результаты версии 0.4.24; проверка следующего выпуска относится к его собственным исходникам и APK.

## Сайт: проверка публикации продолжается

В [коммит f7c2e373](https://github.com/orewn/tropnik/commit/f7c2e3738dd4df471da5cd81d4a6f40b3f194372) перенесён точный universal manifest из успешного публичного Android verifier. Источник APK остаётся `add4fd`; источник этой веб-сборки — `f7c2e373`.

Начальный main-запуск [43088009188](https://github.com/orewn/tropnik/actions/runs/43088009188) прошёл полный browser gate и deploy, затем завершился реальной ошибкой публичной проверки: `/tropnik/browser-verification.json exceeds its response budget`. В `f7` явно задан предел чтения полного browser report 32 MiB: сохранённый отчёт выбранного кандидата имеет 16 534 673 байта и превышает прежние 4 MiB. Для остальных ответов прежний предел сохранён; структура, источник и исходные бюджеты самого отчёта проверяются полностью.

**Окончательная публичная проверка сайта не завершена.** Единственная контрольная попытка 2 того же [Pages workflow](https://github.com/orewn/tropnik/actions/runs/43090337179) прошла полный browser gate и проверку привязки отчёта к исходникам. Затем шаг сохранения снимков карты завершился ошибкой (20:36:51 UTC), а загрузка статического артефакта была пропущена. По наблюдению 20:57:32 UTC общий статус build job `130775710983` остаётся `in_progress`, хотя все шаги закончены. Публикация этой попытки не состоялась; причина ошибки выгрузки не установлена. К 21:02 UTC GitHub закрыл workflow со статусом FAILURE; исходная ошибка выгрузки сохраняется. Третья попытка того же приложения не назначалась. Текущее завершение следующей версии и исходные API-наблюдения сохранены в [журнале 0.4.25](release-0.4.25.md).

### Первая попытка окончательного сайта и контролируемый повтор

Его [read-only проверка](https://github.com/orewn/tropnik/actions/runs/43092859775) сверила точные producer/source/artifact, прочитала исходный JSON и сохранила его без запуска приложения; [результат инспекции](verification/pages-f7-failure-inspection.json) не является допуском выпуска.

В окне 19:57:36.526–19:57:51.538 UTC камера и маршрут оставались стабильными. Векторные данные текущего масштаба z11 уже отображались; до готовности нового рельефа сохранялся предыдущий. Последние 32 завершённых сетевых запроса вернули HTTP 200; три следующих запроса DEM начались примерно за 115 мс до остановки. В сохранённой инспекции карты — пять ожидающих заданий, три загрузки, два задания в очереди, без ошибок. Сохранённые отмены предшествуют окну ожидания. Это показывает продолжающуюся загрузку и чувствительность её общей длительности к сетевым задержкам; внешний outage, deadlock или полная эффективность очереди этим ограниченным хвостом не доказаны.

В **20:06:07 UTC**, до вызова повторного запуска, зафиксирован [план единственного контрольного повтора](verification/pages-f7-controlled-retry-policy.json): точный `f7c2e373`, исходные 15 секунд, все профили, native inputs, бюджеты и детализация сохраняются. Предварительной загрузки тайлов и пропуска ожидания нет. При повторении той же причины дальнейшие неизменённые retries запрещены этим планом; требуется разбор воспроизводимой задержки и исправление продукта. Первый отказ сохраняется независимо от результата второй попытки.

## Производительность и отклонённый эксперимент

Полный браузерный допуск выбранного `1710` [прошёл](https://github.com/orewn/tropnik/actions/runs/43077619318). [Проверка сохранённого полного отчёта](verification/full-browser-1710-inspection.json) показывает desktop map-pan P95 всего окна 33,6 мс и активного жеста 37,8 мс на EPYC 7763. Отдельный UI-прогон с 35,3 мс при исходном пределе 35 мс сохранён как отрицательный результат. Это вариативность программного рендера, а не основание обещать стабильные 60 FPS.

[Единственная заранее определённая A/B-пара](https://github.com/orewn/tropnik/actions/runs/43086722736) сравнила выбранный `1710` с полной очисткой Canvas `8a12` на одном Xeon 6973P-C. Все исходные 8×2 UI-сценария обеих версий прошли; 31 engine test и 46 троек / 138 PNG доказали только корректность экспериментальной отрисовки. Активный desktop P95 составил 32,3 → 32,6 мс, средний интервал 23,90 → 21,78 мс, максимум input-to-next-frame 48,5 → 47,4 мс. Предварительное условие улучшения P95 минимум на 10% не выполнено: `selection.retain=false`, правка отклонена. [Полный отчёт сравнения](verification/canvas-discard-ab-2026-11-11.json) сохранён.

[Исправленная привязка предыдущего A/B](verification/clear-ab-sealed-source-2026-11-11.json) также сохраняет все первоначальные результаты и заголовки. При повторной проверке без запуска приложения прочитаны реальные байты 2109 source inputs каждой стороны, проверены полная опись 2110 записей и исходные buildId.

### Объединённый кандидат: проверка 11 ноября

Ниже отделены результаты отдельных воспроизводимых экспериментов от ещё необходимого полного допуска объединённого commit. Старые разделы этого журнала описывают историю, включая уже удалённые Leaflet и MapLibre; текущий продукт использует собственный общий движок.

- Исправлен контур выбранной территории: заливка исходных полигонов отделена от настоящих линий границы. Добавлена регрессия на реальных данных Чукотки. Адресная проверка подписей читает реальные записи и не теряет нужное название из-за общей выборки в 512 записей.
- Пропуск полностью скрытой непрозрачными детальными тайлами подложки доказан на 46 парах изображений с нулевой разницей. В отдельном обычном прогоне все восемь сценариев интерфейса прошли на обоих профилях; desktop pan p95 составил 24,3 мс при прежнем пределе 35 мс. Это интервалы callback, а не измерение FPS физического телефона. [Прогон](https://github.com/orewn/tropnik/actions/runs/43060178548), [данные проверки](verification/custom-engine-underlay-performance.json).
- Карточка источников сохраняет свою геометрию при загрузке. На коротком горизонтальном экране текст и прокручиваемое окно лицензий остаются в доступной области. Контролируемая проверка прошла 40 случаев на пяти профилях, 131 цикл загрузки, 110 проверок ссылок, 90 настоящих Tab и шесть wheel events. [Прогон](https://github.com/orewn/tropnik/actions/runs/43061176332), [данные проверки](verification/map-attribution-final.json).
- Специализация shader для сплошной маски сохранила пиксели во всех 20 парах, но сама по себе не решила паузу GPU: максимум изменился с 850 до 845 мс. [Доказательство качества](verification/terrain-full-mask-pixels.json).
- Перенос только завершённого GPU-кадра сохранил прежние MSAA, сетку, DPR и пиксели во всех 20 парах с закреплённым старым renderer; исходная четырёхслучайная проверка маски также сохранена. [Прогон](https://github.com/orewn/tropnik/actions/runs/43062875889), [доказательство](verification/terrain-presentation-pixels.json).
- В отдельном прогоне неизменённых 28 zoom inputs максимальная наблюдавшаяся задача сцены уменьшилась с 845 до 126 мс при пределе 350 мс. Этот прогон **не является допуском выпуска**: старая CSS-карточка ещё давала чрезмерный CLS, а close screenshot был сделан до готовности нового кадра. Последующее чтение zoom=5 не доказывало содержание PNG. Это сохранённый отрицательный результат, а не скрытая успешная проверка. [Прогон](https://github.com/orewn/tropnik/actions/runs/43062659824), [подробности](verification/terrain-deferred-performance.json).
- Проверка снимков теперь требует нужный завершённый кадр и одинаковую идентичность непосредственно до и после единственного захвата. Пять снимков, 28 zoom inputs, поворот, сброс, прежние задержки и непрерывные счётчики сохранены. Повторный [прогон с привязкой кадров](https://github.com/orewn/tropnik/actions/runs/43066628100) прошёл: все пять снимков относятся к нужным завершённым ракурсам, а SHA256 исходного и close PNG совпали с ранее независимо проверенными эталонами. Максимальная наблюдавшаяся задача составила 171 мс при пределе 350 мс. Runner использовал другой CPU, поэтому изменение 126→171 мс не приписывается проверке кадров. Дополнительное ожидание close составило 785,5 мс и не объявляется мгновенным показом или измерением FPS. Прежняя ошибка CLS в этом изолированном прогоне сохранена; объединённая CSS-правка проверяется полным допуском.

Пока обязательны новый полный прогон объединённого источника, сборка Android и восемь сценариев действительно установленного universal APK. Затем должны быть проверены опубликованные байты, фактический сертификат, новый manifest сайта и публичный Pages build. До выполнения этой цепочки последним опубликованным выпуском остаётся 0.4.23-preview.

### Исправления после d01e6e9

Полный браузерный прогон дошёл до горизонтального телефона и обнаружил пересечение Layers с панелью карты на 31×44 пикселя: CSS резервировал 208 пикселей для панели фактической шириной 239. Резерв теперь рассчитывается из пяти кнопок по 44 пикселя, разделителя, отступов и границ, с дополнительным промежутком 8 пикселей. Отдельная браузерная проверка использует настоящие JSX и скомпилированные CSS; отрицательный контроль обязан воспроизвести прежнее пересечение.

Трасса масштабирования показала повторную компиляцию неизменившихся границ в `Path2D`, включая длительные `closePath`. Движок теперь повторно использует пути неизменившихся объектов покрытия и собирает новые коллекции в исходном порядке. Координаты, отверстия, части и переход через 180-й меридиан сохранены; изменяемые маршруты не кэшируются. Подписи используют отдельное полотно того же размера и DPR.

Исправлен и подтверждён отдельным A/B дефект браузерного стенда. Эмулированная страница 1440×1000 выходила за фактическое клиентское окно 780×493, поэтому часть изменений справа не попадала в вывод кадра. При клиентском окне 1920×1833 и прежних профилях/DPR/вводах задержка Layers составила 48 вместо 368 мс. Все 17 PNG проверки маски совпали побайтно, включая настоящий WebGL2 и восстановление контекста. Один фиксированный профиль использует программную композицию страницы и SwiftShader для WebGL; actual CDP receipt закрепляет Chrome, GPU, CPU/OS, исходный commit и физическое покрытие всех пяти экранов. Полный отчёт и pixel proof обязаны совпадать по этой среде.

Этот A/B **не прошёл общий допуск производительности**: на неизменённых старых исходниках остались desktop pan p95 36,5 мс при бюджете 35 и пауза zoom 158 мс при бюджете 150. Они не исключены из отчёта. Новый движок после оптимизации должен пройти обычный полный прогон без trace; диагностический success не заменяет приёмку. [Доказательства и первичные источники](verification/custom-engine-browser-environment.json).

Android-стенд теперь проверяет версию того же headless-движка, которым запускает устройство. На SDK emulator 37.2.13 обычный `-version` выбирал оконный QEMU и завершался кодом 127 из-за PulseAudio, а `-no-window -version` прошёл за 44 мс без этой библиотеки. Лишний установщик оконной зависимости удалён. Проверка KVM, фактического графического драйвера, точных APK-байтов и все восемь сценариев устройства сохранены; проверка версии сама по себе не является исполнением этих сценариев.

### Исправления после кандидата 08e5bda

- Счётчик Байкала и остальные счётчики обходят реальные панели. Подписи учитывают уже размещённые числа; географические флаги не перемещаются. Изменение каталога вызывает один отложенный перерасчёт, без цикла от собственных DOM-записей.
- Загрузка и декодирование чередуют слои: DEM больше не стоит за всей очередью векторных тайлов. Отмена устаревшего вида освобождает его HTTP-заявки, сохраняя других потребителей общего ресурса.
- Worker переиспользует реальные края DEM через отдельный кэш 64 записей / 2 МиБ. Полные родительские DEM по-прежнему ограничены 4 записями / 24 МиБ. Разрешение, высоты, рендер 512 пикселей, 3 загрузки, 6 готовящихся заданий, один декодер и прежние критерии приёмки сохранены.
- Смена маршрута сразу снимает прежнюю линию и её область нажатия. Запоздалые ответы принадлежат только текущему выбору. Открытая 3D-сцена принимает новую линию без повторной подготовки высот и сброса камеры.
- Ошибки и неполное отображение линии не исчезают после успешного кадра рельефа. Портретный общий обзор передаёт в 3D пересечение видимого участка с исходными границами карты; недопустимая полярная область не запрашивается.
- Общий runtime пересобран для web и Android. Офлайн-реестр и версия Service Worker обновлены вместе с именами и хешами новых ресурсов.

2. Получить полный браузерный PASS окончательного SHA, включая холодный Алтай, счётчик Байкала, режимы карты, офлайн-сценарии и прежние бюджеты плавности.
3. Пересобрать и проверить точные установленные байты универсального Android APK.
4. Опубликовать неизменяемый release, затем связать веб-загрузку с его SHA-256 и подтвердить публичный Pages build.

Сохраняются ранее документированные границы продукта: справочный каталог, ограниченный подробный офлайн-пакет, development/debug подпись и отсутствие развёрнутого Go API/PostGIS. Проверки эмулятора не являются проверкой физического ARM64 или полевой навигации.

### Второй проверочный кандидат

Промежуточный `ab91c12` прошёл прежние блокирующие сценарии: загрузку высот на Алтае и нажатие на счётчик Байкала в портретном режиме. Подробности: [промежуточное доказательство](verification/custom-engine-ab91.json).

Следующий кандидат добавляет отдельную маску отображения России в 3D. Worker получает только границы участка и загружает необходимые ячейки действующего покрытия. Маска занимает не более 2048×2048 байт; высоты и их происхождение не изменяются. Отсутствующие данные, ошибка, отмена и превышение срока подготовки не открывают прямоугольную поверхность. WebGL и Canvas используют одну маску; широкая линия маршрута и восстановленный GPU-контекст сохраняют её. Общий вид использует прежний overview LOD, подробный вид — соответствующий LOD исходного покрытия, поэтому это маска отображения с существующей точностью данных.

Измерение на фактических локальных ресурсах: общий вид использовал manifest и base (3,08 МБ чтения, около 1,30 с подготовки), Кавказ — одну подробную ячейку, Чукотка через 180-й меридиан — четыре. Эти измерения подготовки не являются браузерным FPS или проверкой физического телефона. Отдельный настоящий Chromium gate проверяет пиксели WebGL2 и Canvas, отверстия маски, широкую линию, поворот, приближение и потерю/восстановление контекста.

Обновление результатов поиска теперь меняет DOM-маркеры без перерисовки полотна карты. Повторный замер неизменных препятствий также не инвалидирует пиксели. Полотно получает отдельный compositor layer; почти непрозрачные панели и шапка используют сплошной фон без повторного размытия карты. Размеры, DPR, данные, детализация и прежние бюджеты приёмки сохранены. Эти изменения ещё требуют измерения на новом SHA.

В 3D уведомления получили отдельные состояния `renderer-error` и `route-warning`. Проверка ожидает готовую картографическую текстуру и прерывается только при ошибке renderer; требование реальной текстуры осталось прежним.

### Исправления по реальным результатам 54c32f0

Полный локальный набор этого checkpoint прошёл 614/614. Android CI снова подтвердил сборку и восемь сценариев точного universal APK. WebGL pixel gate подтвердил отсутствие утечек маски и толстой линии в исходном и повёрнутом приближённом ракурсе, но выявил отказ восстановления контекста; полный browser gate не запускался после этого отказа.

Причина исправлена в жизненном цикле GPU: после потери контекста браузер уже аннулировал старые ресурсы, поэтому их ссылки освобождаются без вызовов GL с недействительными handles. Восстановление создаёт новые ресурсы, сохраняя высоты, маску, картографию, маршрут и камеру. Строгая проверка поколений объектов воспроизводит отказ старого renderer. Пиксельная проверка теперь читает прикреплённое полотно после возможной подмены и по-прежнему требует настоящий WebGL для GPU-сценариев.

Свежая трасса UI показала ещё пять поверхностей с backdrop blur. При минимизации CSS стандартное отключение фильтра исчезало из-за порядка legacy-префикса. Порядок исправлен во всех затронутых правилах; отдельная проверка компилирует настоящие CSS фактическим production-minifier и проверяет сохранение стандартного свойства. Полотно карты удерживает отдельный compositor layer. Бюджеты, DPR, разрешение и данные не уменьшены; устранение превышений требует нового измерения.

Дополнительно браузерная приёмка настоящей 3D-сцены теперь требует совпадения границ, версии покрытия, размеров и числа разрешённых пикселей подготовленной маски с фактически нарисованным кадром. Синтетический pixel gate сам по себе не считается доказательством загрузки production coverage.

### Требования приёмки

Результат импорта должен перечислить все опрошенные территории, найденные и исключённые записи, ошибки запросов, географические пробелы и точные количества до/после. Нулевой результат конкретного источника не означает отсутствие троп на местности. Ни одна импортированная запись не получает полевую верификацию, разрешение на посещение или статус готового навигационного трека автоматически.

Проверки включают происхождение и неизменность геометрии, совпадение web/Android, поиск и фильтрацию, типы, полную браузерную матрицу и реальные сценарии установленного универсального APK. Действующие ограничения задержек, масштаба, DPR и детализации сохраняются. Публикация и конкретные файлы будут записаны только по фактическим результатам.
