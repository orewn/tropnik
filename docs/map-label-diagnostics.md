# Снимки источников подписей карты

Для разбора повторяющихся подписей нужен реальный снимок загруженных объектов и фактически отрисованных символов. Синтетический пример близких координат из разных масштабов показывает возможный механизм, но не устанавливает происхождение конкретного дубля. Нельзя объединять одноимённые места по произвольному расстоянию или считать любой `feature.id` глобальным идентификатором населённого пункта.

`bindMapLabelCoverage` устанавливает на свой контейнер один обработчик события `tropnik:inspect-map-labels`. Сам обработчик ничего не запрашивает до явного события, не запускает таймеров и не сохраняет полученный результат. Он снимается вместе с основным binder при `dispose` или `remove`. Событие содержит только `detail.request`; результат синхронно возвращается в `detail.result`. Ссылки на карту, callback и внутренние объекты движка не передаются.

Запрос ограничен 16 существующими слоями `symbol`, относящимися к проверенному источнику подписей `place`, восемью названиями и 100 точечными объектами в каждой возвращаемой коллекции. Неверный запрос отклоняется до чтения объектов. Для результата вызываются только публичные методы `getStyle`, `getCenter`, `getZoom`, `getBearing`, `getPitch`, `project`, `querySourceFeatures` и `queryRenderedFeatures`. Источники, камера, стили и загруженные тайлы не изменяются; новых сетевых запросов нет.

Снимок содержит три отдельных наблюдения:

- исходные `place`-объекты, возвращённые публичным запросом движка;
- объекты прошедшего географическую фильтрацию источника `tropnik-covered-labels`;
- фактически отрисованные объекты выбранных слоёв.

Для каждого объекта сохраняются ID, координаты, положение на экране, небольшой список свойств названия и идентичности, названия остальных свойств и необязательное поле `observedTile`. Возвращённые движком координаты тайла рассматриваются только как диагностическое наблюдение. Их отсутствие допустимо; алгоритм отображения от них не зависит. Снимок явно содержит `idScope: not-established`. Повторяющиеся ID и близкие координаты сохраняются без объединения. Изменение возвращённой метаинформации не меняет исходный стиль.

В `browser-coast-audit.mjs` снимок запрашивается на пяти существующих кадрах Приморска: z7, z9, z12, z15 и z18. Имена Приморск, Малые Сопки, Карасёвка, Карасевка и Выборг задаёт сам браузерный сценарий, а не код отображения. Перед запросом кадр уже сохранён в PNG; снимок связывается с именем файла и его SHA256. Состояние камеры до и после чтения должно совпадать, а масштаб и центр — соответствовать записанному кадру. Усечение коллекции объектов или ID делает диагностический снимок непригодным для приёмки; список названий необязательных свойств остаётся ограниченной справочной выборкой.

Coast schema 2 сохраняет все прежние проверки геометрии, настоящих жестов, zoom и изображений и дополнительно требует пять таких снимков в WebGL. Canvas не получает фиктивных WebGL-снимков. Запросы выполняются после уже сохранённых интервалов modes и sourceEnds; следующий спутниковый сценарий открывает новый документ с собственными измерениями. Поэтому дополнительные чтения не подменяют и не уменьшают существующие измерения производительности.

Локальные тесты проверяют пределы, отсутствие запросов до события, снятие обработчика, неизменность камеры/источника, сохранение двух близких копий с одинаковым ID, отсутствие внутреннего состояния движка в ответе и отказ при неполном либо привязанном к другому кадру receipt. Они не доказывают, что дубли устранены. Такое решение требует последующего просмотра настоящих снимков из полного CI.

Предварительное независимое чтение восьми реальных MVT OpenFreeMap сохранено в [source-only evidence](verification/map-label-source-observation-0.4.24.json). У Приморска на z7–14 совпадает ID, но различаются квантованные координаты; аналогичная пара найдена для Карасевки. Версия набора, URL, размеры и SHA256 закреплены в отчёте. Это подтверждает возможный механизм, но не состав загруженных объектов конкретного браузерного кадра. Отчёт не допускает релиз и не заменяет PNG/capture из CI.
