# Маршруты из poiskpohod: импорт с проверкой редактором

## Текущее состояние

История сообщений `https://t.me/poiskpohod` не была получена. Открытая страница группы не заменяет доступ к сообщениям. В `web/lib/telegram-reviewed.generated.json` намеренно **0 маршрутов и 0 ссылок на сообщения**, статус `pending_history_access`. Нет утверждения, что чат изучен или его сообщения уже включены в каталог.

Инструменты готовы принять JSON одного чата, экспортированный человеком с законным доступом через Telegram Desktop. Они работают локально, не входят в Telegram, не запрашивают сообщения по сети, не скачивают GPX и не читают вложенные файлы. Автоматический этап создаёт только закрытую очередь кандидатов. Публичный каталог меняется отдельной командой после явного решения редактора.

## Получение входных данных

В Telegram Desktop откройте нужную группу, выберите меню экспорта истории чата и формат **JSON**. Экспортировать медиафайлы для обнаружения упоминаний необязательно. Нужен экспорт именно этой публичной группы, а не всей учётной записи, личного диалога или списка участников. Большую историю разделите на диапазоны дат: предел одного файла — 64 МиБ и 50 000 сообщений.

Сохраните входной файл в `tools/import-data/telegram/private/result.export.json`. Каталог `private/`, файлы `*.export.json` и `*.queue.json` исключены из git правилами в каталоге инструмента. Не добавляйте исходный экспорт, очередь или заполненные решения в публичный репозиторий и артефакты сайта. При публикации через API, которая обходит gitignore, эти пути также следует исключать явно.

Формат Desktop не всегда содержит публичное имя группы. Поэтому имя/числовой ID экспортированного чата **не считаются доказательством** связи с `poiskpohod`: редактор подтверждает правильный чат и открывает каноническую ссылку каждого одобряемого сообщения. Поле `sourceChatConfirmed` означает именно эту ручную проверку. Если история относится к миграции группы или сообщения по такой ссылке недоступны, кандидат не одобряется до проверки корректного источника.

## Обнаружение кандидатов

Требуются Python 3.10+, Node.js и установленные зависимости `web/`. Из корня проекта:

```sh
python3 tools/import-data/telegram/cli.py discover \
  tools/import-data/telegram/private/result.export.json
```

Команда создаст `private/review.queue.json` и `private/review-decisions.json`. Выводятся только числа и пути, без текста сообщений. Повторный запуск не перезапишет файл решений: задайте новый `--review-template`. Для объединения диапазонов передайте старую очередь через `--previous-queue`; `--out` задаёт новый путь очереди внутри `private/`.

Парсер поддерживает обычный `text`, смешанные массивы строк и сущностей, а также `text_entities`. Сервисные события, сообщения без маршрутных признаков и неподдерживаемый формат `rich_message` пропускаются с отдельными счётчиками. Признаки маршрута — точное совпадение названия/источника с текущим каталогом, явно обозначенное название маршрута, GPX или маршрутная ссылка вместе с походным контекстом. Это консервативная эвристика: она может пропустить упоминание или предложить лишний кандидат, поэтому очередь не публикуется автоматически.

Для кандидата сохраняются:

- ID сообщения, исходная дата и дата редактирования, если она есть;
- каноническая ссылка `https://t.me/poiskpohod/{messageId}`;
- возможные совпадения с маршрутами текущего каталога и подсказки известных регионов;
- безопасные публичные ссылки, включая ссылки на GPX;
- наличие GPX-вложения и ссылка на сообщение, где его можно проверить;
- контрольная сумма записи очереди, состояние `review_required` и признак конфликта.

**Не сохраняются** участники, имена авторов, ID пользователей, телефоны, электронные адреса, пересылки, ответы, исходные тексты, подписи файлов или локальные пути к вложениям. Даже предполагаемое название нового маршрута не копируется из свободного текста: редактор вводит его после чтения источника. Из URL удаляются фрагменты и произвольные параметры, включая токены доступа; остаются только числовые параметры идентификаторов маршрута. Личные профили, локальные адреса и небезопасные схемы исключаются. Ссылки из очереди не переносятся в публичную карточку автоматически.

Ограничения входа включают глубину JSON, размер текста, число сущностей и ссылок. Повторные ключи JSON, NaN/Infinity, символьные ссылки на входной файл и некорректные даты отклоняются. Числовой ID сообщения обязателен; строка, отрицательное число или boolean не преобразуются в ID. Часовой пояс не придумывается: дата сохраняет форму и смещение из экспорта.

Повторный ID с теми же извлечёнными данными не дублируется. Если новый экспорт даёт для того же ID другие значимые поля, кандидат получает `conflict: true` и не публикуется. Разберите конфликт, выберите достоверный экспорт сообщения и создайте новую очередь/решение. Контрольная сумма связывает решение с записью очереди; она не является подписью Telegram или доказательством подлинности выгрузки.

## Ручное решение

Сгенерированный шаблон содержит `sourceChatConfirmed: false`, а каждое решение — `decision: "pending"`, `sourceRead: false`, `privacyReviewed: false`, `reviewedAt: null`. Такие записи ничего не публикуют.

Редактор читает сообщение по его ссылке, проверяет предмет упоминания, отсутствие личных данных, совпадения в каталоге и принадлежность российскому направлению. Имя файла, имя группы, подсказка региона или ссылка на GPX не заменяют проверку.

| Поле решения | Значение и назначение |
| --- | --- |
| `sourceId`, `candidateDigest` | Оставить без изменений из шаблона. |
| `decision` | `pending`, `reject`, `attach_existing` или `new_reference`. |
| `sourceRead` | `true` только после чтения точного исходного сообщения. |
| `privacyReviewed` | `true` только после проверки данных для публикации. |
| `reviewedAt` | Реальная дата/время проверки в ISO-формате, не ранее публикации сообщения. |
| `existingRouteId` | Для `attach_existing`: точный ID уже существующего маршрута. |
| `regionConfirmedForRussia` | Для `new_reference`: явное подтверждение принадлежности российскому направлению. |
| `route` | Для `new_reference`: только `title`, `description`, `regionId`. Название и краткое описание пишет редактор без контактов, участников, разметки и непроверенных характеристик. |

Допустимые `regionId` берутся из действующего `web/lib/content.ts`; новое или иностранное направление нельзя добавить строкой из сообщения. При найденном совпадении используйте `attach_existing`: новая карточка отклоняется, чтобы не дублировать маршрут. Совпадения названий сравниваются после нормализации регистра и пунктуации. Если один батч содержит одинаковое проверенное название в одном регионе, сохраняется одна карточка с несколькими ссылками на сообщения.

Проверенные решения применяются командой:

```sh
python3 tools/import-data/telegram/cli.py publish \
  tools/import-data/telegram/private/review.queue.json \
  tools/import-data/telegram/private/review-decisions.json
python3 tools/import-data/telegram/cli.py validate
```

Для предварительного просмотра результата можно указать `--out tools/import-data/telegram/private/proposed-catalog.json`, затем сравнить его с публичным JSON. Публикация в GitHub/Pages остаётся отдельным обычным процессом проекта. Команда `publish` записывает локальный JSON атомарно и не отправляет данные в сеть.

## Что появляется в Tropnik

Новый маршрут имеет `sourceKind: "community"`, `publicationStatus: "reference"`, неизвестную сложность и `null` для расстояния, времени и набора высоты. Он не получает `geometry`, `geometryUrl`, `center` или `bbox`. Регион задаёт редактор; это принадлежность справочному разделу, а не измеренная географическая привязка. Карточка не является навигационным треком и не должна превращаться в выдуманную точку/линию на карте.

Для существующего маршрута добавляется только проверенная ссылка на упоминание. Она не заменяет первичный источник геометрии и не повышает статус готовности маршрута. Для нового маршрута ссылка на исходное сообщение является первичным источником карточки.

Публичное происхождение использует согласованную структуру `additionalSources`:

```ts
type SourceReference = {
  url: string;
  name: string;
  messageId: number;
  publishedAt: string;
  reviewedAt: string;
  scope: 'community_mention';
};
```

`publishedAt` — дата сообщения, `reviewedAt` — дата проверки ссылки редактором. Ни одна из них не означает проверку маршрута на местности. Данные участников в структуре отсутствуют. `content.ts` объединяет новые справочные карточки и ссылки на существующие маршруты; ссылки дедуплицируются по каноническому URL.

## Проверки и источники формата

```sh
python3 -m unittest discover -s tools/import-data/telegram -p 'test_*.py' -v
python3 tools/import-data/telegram/cli.py validate
```

Тесты используют исключительно синтетические фикстуры. Проверяются ограничение входа, смешанные сущности, пропуск переписки, фильтрация контактов и URL, отсутствие чтения GPX, дедупликация, конфликт ID, совпадение с каталогом, обязательность ручных подтверждений, защита от геометрии/метрик/неизвестного региона и идемпотентность публикации. Эти команды включены в workflow Pages перед сборкой.

Первичные источники: [официальное описание экспорта Telegram Desktop](https://telegram.org/blog/export-and-more), [официальная справка об экспорте чата](https://bugs.telegram.org/c/60), [реализация JSON-экспорта Telegram Desktop](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/export/output/export_output_json.cpp). Формат следует фактическим полям JSON-писателя; нет зависимости от стороннего API, скрейпера или списка участников.

**Остаток, требующий входных данных:** получить законный экспорт истории `poiskpohod` или доступные точные сообщения и провести редакторскую проверку. До этого публичный Telegram-набор остаётся пустым.
