## Состав обновления

Веб 0.4.3 позволяет выбирать 85 элементов закреплённых картографических источников: 83 объекта RUS ADM1 и два ранее выбранных объекта UKR ADM1. Это состав исторического слоя отображения. Современный юридический административный состав этим числом не устанавливается. Идентификаторы наборов, исходные атрибуты и контрольные суммы сохранены в [территориальной metadata](../web/lib/territories.generated.json).

Есть поиск по русским названиям, силуэты из исходной географии, выделение границы и кадрирование всей выбранной территории. Шесть туристических направлений остаются отдельными подборками. Поиск «Байкал» находит направление и подходящие по названию территории.

Встроенный каталог содержит **277 справочных маршрутов**. Их связь с территорией вычисляется через пересечение исходной линии с исходным полигоном, с учётом сегментов, отверстий, разрывов и перехода через 180°. Для расчёта инвентаризировано 280 файлов геометрии; это отдельный счётчик исходных файлов. **Полевой проверки полной геометрии — 0; подтверждённой готовности к навигации — 0.**

Исправлены сброс готового Canvas-слоя при переключении троп, восстановление выбранной основы после возвращения сети, потеря видимости слоёв после style.load и запоздавшая отрисовка старого маршрута. Освещение hillshade остаётся привязано к камере без покадровой перезаписи контраста. Мобильное кадрирование учитывает открытую панель и завершение её анимации; начатое пользователем управление отменяет автоматический повторный fit.

### Управление офлайн-картами

Установка и удаление пакета используют общую межвкладочную блокировку. Старый исправный пакет сохраняется при повреждённом или отменённом обновлении. Ошибка уборки после публикации новой версии не удаляет новую рабочую копию. Статус в интерфейсе перечитывается из фактического хранилища.

Устранена коллизия маршрута **/offline**: статический файл public/offline.html перехватывался HTML-маршрутизацией Cloudflare раньше страницы приложения. Теперь **/offline открывает управление скачиванием**, а автономный просмотрщик имеет отдельный адрес **/offline-viewer.html**. Старый файл удалён, ссылки и статическая сборка обновлены, service worker использует **tropnik-shell-v10**. Переход без сети сохраняет fallback к просмотрщику в корне сайта и под базовым путём статической сборки. Запросы API/auth не получают этот fallback и не сохраняются в CacheStorage.

Обязательный Node build gate проверяет файлы оболочки, территориальные данные и SHA256 исходной геометрии до framework build. Он также отклоняет повторное появление public/offline.html, которое вернуло бы конфликт со страницей управления.

### Браузерный BFF

BFF проверяет Origin через явно заданный серверный PUBLIC_ORIGIN. Внутренний HTTP-listener и поддельные forwarded headers не предоставляют доверия. HTTPS-origin определяет Secure-cookie при входе и выходе. Подключённый сервис признаётся готовым только при корректной конфигурации и успешном ответе проверки реальной БД.

## Версии и граница поставки

**Android-бинарные файлы не пересобирались: 0.4.2-preview, versionCode 6.** Новые веб-функции выбора территорий, исправления браузерного менеджера пакетов и маршрутизации не приписываются APK. Подписи, содержимое и результаты прежней сборки указаны в [android-parity-0.4.2.json](verification/android-parity-0.4.2.json).

Go/PostGIS не развёрнут и не подключён к preview. Регистрация, подтверждённые группы, чат, отзывы и модерация требуют настоящего API. D1-дубликат Go backend не создавался.

До социального production-запуска нужны реальный HTTPS endpoint Go/PostGIS, штатная проверка миграций и ограниченной роли БД, сквозные проверки групп и модерации, испытание Android на устройстве. Native PostGIS concurrency gate и device/instrumentation gate остаются невыполненными. GitHub Actions ранее отклонял запуск заданий из-за billing/spending ограничения аккаунта; платёжные настройки этим выпуском не меняются.

В source audit остаются интеграционные задачи: приватная история завершённых участий в кабинете; согласование Android 1 MiB response budget с полной геометрией и пагинацией; территориальные идентификаторы или точное пространственное членство для новых маршрутов живого API. Точный территориальный индекс этого выпуска относится к встроенному справочному каталогу. При будущем подключении API его новые маршруты используют туристические направления и раздел походов до реализации территориального членства. Подтверждение email, восстановление пароля и удаление аккаунта требуют отдельной реализации перед открытой регистрацией.

Подробный офлайн-пакет и отдельная объёмная сцена охватывают Бзерпинский пилотный район. Обзор страны и локальные линии справочника не предоставляют подробное автономное покрытие всей России. Gotham Pro и материалы Quixel не включены без соответствующих лицензированных файлов.
