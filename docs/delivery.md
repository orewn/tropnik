# Исходники, APK и передача проекта

## Комплект

Поставка состоит из самостоятельных материалов: ZIP исходников, ARM64 preview APK и универсального preview APK. APK не вложены в ZIP. Исходники включают веб, сервер, Android, контракты, инфраструктуру, воспроизводимые скрипты, геоданные, карты, шрифты и лицензионные уведомления. SDK, установленные зависимости, ключи и локальная конфигурация не требуются получателю внутри архива: они устанавливаются или задаются отдельно.

Не назначайте всему репозиторию лицензию данных OSM или SDK. У сторонних материалов собственные условия, сохранённые рядом с файлами; лицензирование собственного кода определяет владелец. Файлы коммерческого Gotham и Quixel-ассеты в комплект не добавлены.

## Состав источников

| Путь | Включение |
|---|---|
| `web/app`, `components`, `lib`, `hooks`, `public` | Рабочие страницы/компоненты и runtime-ресурсы, включая карты, DEM, глифы, сцены и уведомления |
| `web/scripts`, конфигурация Next/Vite/TypeScript и pnpm lockfile | Воспроизведение обычной Next-сборки и отдельного preview workflow |
| `web/docs`, общий `web/public/terrain/terrain-renderer.js` и его типы | Документация объединения и полный исходник общего WebGL2 renderer, не только готовый HTML |
| `backend` | Go, миграции, операторские команды, тесты, Dockerfile и фактические verification-отчёты |
| `android/app/src`, `app/schemas`, Gradle scripts/wrapper | Kotlin/Compose, Room schema, Android resources/assets и воспроизводимая сборка |
| `contracts`, `infra`, `docs`, `tools`, `.github/workflows` | API, развёртывание, исследования, сборочные инструменты и CI |
| `data/catalog` | 278 исходных нормализованных маршрутов, отдельная геометрия, оригинальные ответы, хеши, источники, матрица и лицензия; RF display scope выбирает 277 |
| `data/boundaries` | Исходные RUS/UKR GeoJSON, download metadata, selection/provenance, проверки, лицензии и атрибуция; воспроизводимый WKB cache исключён |
| `data/pilot-map` | Весь ограниченный MVT пакет с глифами, manifest и лицензиями |
| `data/terrain-pilot/runtime` | Только проверенный runtime DEM-набор, его исходные уведомления и лицензии |
| `data/terrain-pilot/terrain-grid.json`, `landscape.html` | Проверенная сетка и локальная сцена; остальные промежуточные файлы родительской рабочей папки исключены |

Файл `SOURCE-INVENTORY.json` внутри подготовленного snapshot содержит точный список, размеры и SHA256 каждого включённого исходного файла. Сам inventory не перечисляет собственный хеш. Упаковщик повторно сверяет содержимое ZIP с inventory, а не только успешность команды сжатия.

Исторический `data/terrain-pilot/terrain-grid.json` и `landscape.html` сохраняются для аудита первоначального preview. Текущий общий renderer, плотная сетка 513×513 и веб-документ находятся в `web/public/terrain`; Android включает проверенный документ, построенный своим генератором из общего renderer/сетки. Эти платформенные HTML не обязаны совпадать побайтово.

## Два профиля

- **`source`**: полный архив для владельца и аудита. Содержит исходный региональный `.osm.pbf` и большой слой `data/catalog/raw-trails-krym.geojson`.
- **`github`**: тот же запускаемый проект, без этих двух тяжёлых видов исходных данных. Их URL, хеши, provenance и импортер остаются. Нормализованный каталог и **runtime** `.pbf` тайлы веба/Android сохраняются — они не равны большому исходному OSM PBF.

Оба профиля сохраняют первичные boundary GeoJSON: RUS — 59 162 098 байт, UKR — 3 919 902 байта, с исходными SHA и metadata. Из `data/boundaries` исключены только `selected-area-source.wkb` и `selected-area-source-cache.json`, которые воспроизводятся из этих исходников. Они не являются единственной копией происхождения геометрии.

В обоих профилях исключены `node_modules`, `.next`, `dist`, `build`, `.gradle`, `.kotlin`, `_deps`, SDK/toolchains, кеши, окружение исполнения preview, логи, временные файлы, локальные БД, установленные бинарные зависимости, APK/AAB и содержимое `web/public/downloads`, кроме `android-manifest.json`. Этот небольшой JSON импортируется страницей Android при сборке и сохраняется в обоих профилях; бинарный APK передаётся отдельно. Gradle wrapper JAR разрешён как конкретный воспроизводимый bootstrap, а не как SDK.

Исключены реальные `.env*` и `.dev.vars*`, `local.properties`, signing keystore, private-key файлы и credential-файлы; `infra/.env.example` с пустыми значениями сохраняется. Устаревший `web/package-lock.json` не поставляется: актуален `web/pnpm-lock.yaml`. Symlink в выбираемом дереве прерывает сборку, чтобы не выйти за пределы проекта.

## Упаковка

Требуется Python 3, без сторонних библиотек. Команды выполняются из корня проекта. Новая output-папка обязательно находится **вне** исходников; существующая папка не перезаписывается.

```bash
python3 tools/package-project.py --profile source --dry-run
python3 tools/package-project.py --profile source --output ../tropnik-source-delivery
python3 tools/package-project.py --profile github --no-zip --output ../tropnik-github-staging
```

Полная команда создаёт:

- `source/tropnik/` — рассмотренное дерево для чтения/сборки;
- `source-inventory.json` — контрольные суммы и учёт исключений;
- `tropnik-source.zip` — исходники с верхним каталогом `tropnik/`;
- `package-result.json` — итоговый размер, SHA256 ZIP и результат повторной проверки.

`--no-zip` создаёт только staging и inventory. Скрипт ничего не загружает, не коммитит, не меняет ветку GitHub и не подписывает APK. Если исходник изменился во время копирования, подготовка останавливается; после завершения работы над файлами создайте новый snapshot в другой output-папке. Частично созданный каталог при ошибке не считается готовой поставкой.

Встроенная проверка ищет несколько характерных форм секретных токенов/ключей; выводит только имя файла и правило, без значения. Это дополнительный барьер и контроль путей, не утверждение о полноценном security scan. Перед публикацией владелец должен проверить подготовленное дерево и выполнить используемый в проекте секрет-сканер. Экспортные проверки запускаются так:

```bash
python3 tools/test-package-project.py
```

Для GitHub используйте staging профиля `github`. Не загружайте рабочий каталог целиком: там могут появиться новые локальные настройки и продукты сборки. Публикация ветки/релиза — отдельное действие владельца. Начальный репозиторий `orewn/tropnik` был private; упаковщик не меняет visibility.

## APK и отчёты

Имена, SHA256 и технические ограничения двух APK находятся в [Android BUILD-VERIFICATION](../android/BUILD-VERIFICATION.md). `android/dist/` создаётся сборочным скриптом и передаётся отдельно только в нужной части. Instrumentation APK предназначен для тестов, не для обычного пользователя. Локальный debug signing key не передаётся.

Для размещения кнопки загрузки на собственном сайте вручную положите переданный `tropnik-arm64-preview.apk` в `web/public/downloads/` перед Next build. `android-manifest.json` уже включён в исходники: размер/SHA в нём должны соответствовать поставляемому APK; при самостоятельной пересборке обновите их. Не называйте debug APK релизом магазина. Для управляемых обновлений владелец настраивает release signing вне репозитория.

## Проверка получателем

Сравнить SHA256 переданных файлов с сопроводительным результатом, распаковать ZIP, проверить необходимые карты и лицензии по `SOURCE-INVENTORY.json`, установить зависимости из соответствующих lockfiles. Затем повторить [критерии приёмки](acceptance.md), особенно настоящую БД, связку клиентов и Android-устройство. ZIP с корректными хешами подтверждает целостность передачи, а не проходимость маршрутов или готовность production.
