# Область показа карты Тропника

Здесь сохранены первичные данные, генераторные метаданные и проверки области показа. Она составлена из всех 83 объектов RUS ADM1 выбранного снимка geoBoundaries и двух явно выбранных объектов `Autonomous Republic of Crimea` / `Sevastopol` из того же выпуска UKR ADM1, чтобы сохранить существующее туристическое направление «Крым».

Это выбор географического охвата продукта. Он **не устанавливает правовой статус территории**, не подтверждает актуальность границы на сегодня и не определяет разрешение на проход. Имена и ISO исходных объектов не переписываются в provenance.

## Первичные источники

- geoBoundaries RUS ADM1: <https://www.geoboundaries.org/api/current/gbOpen/RUS/ADM1/>.
- geoBoundaries UKR ADM1: <https://www.geoboundaries.org/api/current/gbOpen/UKR/ADM1/>.
- Обе геометрии закреплены на commit `9469f09592ced973a3448cf66b6100b741b64c0d`; URL и SHA-256 загрузок лежат в `raw/*-download.json` и manifest.
- В метаданных указан год представления **2017**, обновление исходных данных у издателя **19.01.2023**, сборка **12.12.2023**. Загрузка в проект в ноябре 2026 года не означает новую съёмку или обновление границ.
- Источник геометрии: OpenStreetMap / Wambacher. Лицензия конкретных наборов: **ODbL 1.0**, а не автоматически общая лицензия всего сайта. Сведения об индивидуальных лицензиях: <https://github.com/wmgeolab/geoBoundaries/blob/main/LICENSE>. Сохранять OSM и geoBoundaries attribution; текст — `ATTRIBUTION.txt`.

В параллельном проекте обзорные `world.geojson`, `regions.geojson` и их metadata побайтно совпадали с нашей версией. Новые границы получены из полного первичного набора: старый упрощённый RUS ADM1 исключал тестовые точки Анадыря и Уэлена. Полный источник включает обе. Старый крымский контур Natural Earth содержал 15 точек; выбранные новые исходные объекты содержат 2 612 точек до объединения.

## Контракт файлов

Все четыре геометрии — GeoJSON `FeatureCollection`. Область содержит один polygonal feature; маска — четыре feature, которые делят плоскость на полосы по 90° и имеют прозрачные отверстия в выбранной области.

| URL | Долготы | Применение |
|---|---|---|
| `/data/russia-display-area.geojson` | 0…360, фактическая область примерно 19.64…191.00 | Leaflet; display point-in-polygon |
| `/data/russia-outside-mask.geojson` | 0…360 | Leaflet inverse fill mask |
| `/data/russia-canonical-area.geojson` | −180…180, разрез у антимеридиана | MapLibre / Native; обмен GeoJSON |
| `/data/russia-canonical-mask.geojson` | −180…180 | MapLibre / Native inverse fill mask |
| `/data/russia-boundaries-provenance.json` | Metadata | `fitBounds`, `recommendedMaxBounds`, размеры, SHA-256, источники |

Display-файлы с долготами более 180° — артефакты для рендерера; для обычного обмена GeoJSON использовать canonical. При проверке точки по display-area отрицательную долготу преобразовать в `lng + 360`. Для canonical оставить обычную долготу. Не вычислять начальный ракурс по raw min/max canonical: получится почти вся планета. `fitBounds` в metadata использует реальные пределы полного выбранного исходника, включая арктические острова.

Маску рисовать только заливкой, **без stroke**, выше базовых подписей/POI, ниже собственных маршрутов и элементов интерфейса. Линии между четырьмя полосами — технические разрезы, не границы. `maxBounds` ограничивает прямоугольник; для исключения действий вне области нужен отдельный point-in-polygon. Геометрию Leaflet нужно показывать в том же непрерывном восточном интервале; `worldCopyJump` сам не дублирует GeoJSON. Начальный обзор — север сверху, pitch 0; минимальный zoom должен позволять вписать всю ширину в доступную область мобильного экрана. Полный исходный fit: `[[19.6389282,41.1858711],[191.0026658,81.858721]]`.

## Точность и размер

Чтобы ограничить стартовый GeoJSON, дальний внешний контур RUS получает topology-preserving simplification с допуском **0.008°** (примерно 891 м по широте; расстояние по долготе зависит от широты). Это параметр генерализации, **не заявленная точность измерения**. Крым и Севастополь остаются в полном разрешении выбранного исходника. Полная детализация также сохранена в объединении envelopes всех 278 импортированных геометрий маршрутов с отступом 0.015°: это предотвращает обрезание маршрутов грубой обзорной линией. Контур в этих областях взят из источника; сами треки не добавляются к территории и не расширяют её.

Два внутренних отверстия исходника — Ладожское и Онежское озёра — включены в область туристического показа **по существующим кольцам исходной геометрии**. Никакая новая внешняя граница или береговая линия не рисовалась. Преобразование явно указано в provenance как display coverage. Исторические административные полигоны также местами включают прибрежную акваторию: это не извлечённая береговая линия. Геометрию нельзя использовать для юридического геофенсинга, проверки права прохода, аварийной навигации или подтверждения точного положения береговой линии на больших масштабах.

Итоговый display-area содержит 46 815 вершин; каждый рабочий GeoJSON занимает примерно 1.11 МБ до HTTP-сжатия. Географические файлы зафиксированы после проверки, SHA-256 находятся в manifest.

Полные исходники занимают около 63 МБ и не загружаются браузером. `selected-area-source.wkb` — локальный кэш полного dissolve, также не входит в runtime. Для приложения нужны только соответствующая пара компактных геометрий, metadata и атрибуция. Не копировать весь `data/boundaries/raw` в APK или web/public.

## Воспроизведение и проверки

```sh
python tools/map-package/build-russia-mask.py
```

Если первичные файлы удалены, `--download-missing` разрешает ограниченную последовательную загрузку тех же закреплённых файлов. SHA-256 и ожидаемые количества исходных объектов проверяются. Автоматического обновления на новый выпуск нет.

`russia-mask-checks.json` проверяет валидность сериализованных геометрий, комплементарность области и маски, преобразование через антимеридиан, 22 контрольных случая: Калининград, Анадырь, Уэлен, остров Врангеля, арктический остров из исходника, обе стороны Чукотки, города Крыма, включённые внутренние водоёмы и ряд исключаемых городов вне выбранного охвата. Точки для севернейшего острова и двух сторон Чукотки помечены как исходно геометрические контрольные точки: это проверка сохранности данных, не независимое полевое подтверждение.

`catalog-mask-coverage.json` содержит построчный отчёт по всем 278 маршрутам и 223 073 вершинам. Ни одна вершина, находившаяся внутри полного выбранного источника с указанными внутренними водоёмами, не потеряна из-за генерализации. `osm-relation-14407325` («к Водопаду») целиком лежит вне выбранного охвата уже в полном исходнике; он записан в `excludedCatalogRouteIds` для исключения из RF-каталога и маркеров. Это географический фильтр продукта, не вывод о доступности, правовом статусе или полевой проверке маршрута.

При обновлении источника нужно повторить эти проверки, сравнить охват маршрутов и визуально проверить обе стороны 180°, острова, побережье, мобильный fit и порядок слоёв маски. Прохождение геометрических проверок не означает автоматическую проверку фактической актуальности границ.
