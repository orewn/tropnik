## Сохранённые исправления 0.4.1 и регрессионные проверки

При невосстановимой ошибке графики общий renderer освобождает ресурсы и сообщает `onFatal`. Веб-host снимает готовность; явный повтор создаёт новый canvas и renderer. Поздние callbacks старой сессии не могут вернуть признак готовности. Для shared renderer и standalone host выполнены **22 теста** (18 + 4), включая отказ после первого успешного кадра. Это управляемые графические fixtures, а не испытание реального GPU.

В Android документ переводится в `failed`; native viewer проверяет состояние видимой сцены каждые 500 мс, удаляет сломанный WebView и показывает кнопку повторной подготовки. Повтор создаёт новый WebView с уже проверенным локальным документом. Готовая скрытая сцена не опрашивается и не перерисовывается. Шесть Node-тестов generated bootstrap проверяют также terminal failure и глобальную ошибку после готового кадра; поздний `onRender` не отменяет отказ. Пятый instrumentation сценарий проверяет замену WebView после document failure, но он только скомпилирован.

Публикация локального пакета защищает короткую запись в Room через `NonCancellable`, отмечает переход владения каталогом до выхода из секции и сохраняет `CancellationException` для вызывающего кода. Копирование и проверка остаются отменяемыми. Ошибка удаления прежней копии не удаляет новую опубликованную. Три JVM-теста воспроизводят отмену после commit, отказ записи и сбой последующей очистки на настоящих файловых каталогах с управляемым DAO callback; живую Room-транзакцию они не запускают.

## Сохранённая связь готовности с интерфейсом

Запуск с настроенным сервисом, восстановление сети, смена адреса или нажатие **Обновить** → `OnlineViewModel.refreshData` → `ApiClient.checkHealth` → `GET /api/v1/health/ready`. Backend вызывает `Store.Ready`, выполняющий `SELECT version FROM schema_migrations WHERE version=$1` с `migrations.RequiredVersion=3`: проверяются доступ к базе и требуемая миграция. Android проверяет публичную ready-envelope и не фиксирует номер серверной миграции в своём протоколе.

Готовность принимается только при HTTP 200, `data.status="ready"`, `meta.mode="production"` и отсутствии `error`. HTTP 503 даже с ready-телом, liveness `ok`, `not_ready`, неверная/неполная envelope, preview mode, `error`, HTML, 204 и 202 её не подтверждают. Публичный запрос не отправляет Bearer.

`ServiceStatus` разделяет checking/ready/unavailable, отсутствие адреса, отсутствие сети и состояние входа. Timestamp старых данных не подтверждает готовность. Смена сети, 503 и транспортная ошибка снимают старое подтверждение. Автономная карта от этого не зависит. Связь с UI скомпилирована и проверена чтением кода; выполнение на устройстве и обращение к живой PostGIS не заявляются.

### Рельеф и 3D-сцена

Включены **21 DEM тайл PNG256/Terrarium** на z7–12, архивная сетка 129×129 с 16 641 числовой высотой, атрибуция/лицензии Mapterhorn/Copernicus. Все 48 записей DEM manifest проверены по размеру и SHA256. Область `[40.29,43.64,40.49,43.82]` покрывает пилот Бзерпина; встроенная подробная офлайн-подложка не покрывает Хосту, весь Краснодарский край или Россию. Для остальных районов предусмотрена отдельная подгрузка подробной карты по сети.

Общий с вебом renderer встроен в автономную сцену **1 990 035 байт**, меньше лимита 2 МиБ. Сетка 513×513 содержит **263 169 высот**. Выборка около 31,42×39,14 м получена из сохранённых DEM; это не новая съёмка и не доказательство более высокой измерительной точности. Генератор фактически пересчитал производную и проверил provenance перед сборкой.

```text
41743ade3e96408b0687515d770903497fddb139587f64e45af5f8d74384194a  landscape.html
```

Проверены встроенная сетка, границы, provenance, точные CSP хэши скриптов/CSS, шрифты и отсутствие внешних ресурсов. Локальные ресурсы используют `asset://`. Полный стиль содержит два явно разрешённых сетевых источника; при локальном режиме `MapStylePolicy` удаляет их до вызова MapLibre. Сеть в 3D WebView по-прежнему полностью запрещена. Сохранены отдельные OFL для нативного Manrope и шрифтов сцены, лицензия Copernicus GLO-30 и обязательное уведомление об ответственности.

Документ проверяется native кодом до загрузки. Прикреплённый WebView готовит кадр за непрозрачной карточкой; кнопка 3D включается после сигнала renderer и `postVisualStateCallback`. Возврат сохраняет тот же WebView и позицию карточки. Скрытый viewer исключён из ввода, фокуса и accessibility; готовая скрытая сцена приостанавливается. Незавершённая подготовка отменяется в фоне и допускает повтор. Потерянный процесс WebView удаляется и не используется снова.

WebView блокирует сеть, внешние переходы, новые окна, доступ к файлам/content, геолокацию и разрешения. JavaScript interface отсутствует, аккаунт и токены не передаются. Передаются только фиксированные события жизненного цикла и читается готовность кадра. Глобальные cookies и таймеры других WebView не изменяются.

**MapLibre Native 13.7.1 сам не строит terrain mesh**: наклон основной карты является перспективой плоскости; отмывка склонов привязана к камере. Реальная модель высот находится в отдельном локальном viewer. Он использует WebGL при доступном графическом backend и программный fallback; 60 fps на Android не измерены и не заявляются.

В карточке 8А сохранено официальное ограничение с 27 октября 2026: открыт участок до Бзерпинского карниза, лагерь Холодный закрыт. OSM-линии показаны справочно; точная граница закрытого сегмента не придумана. Источники и даты указаны в каталоге и `SOURCES.txt`.

## Границы проверки

Следующее **не выполнялось** и не обозначается пройденным:

- Запуск пяти Android instrumentation/Compose сценариев: они скомпилированы. Эмулятор и устройство в этот прогон не запускались.
- Визуальная проверка Android compositor, системных разрешений, TalkBack, большого системного шрифта, поворота и потери WebView-процесса на телефоне.
- Реальный airplane mode, полевой GPS fix, расход батареи, нагрев и кадровая частота. Проверена статическая автономность ресурсов.
- Сквозная регистрация/чат/группа с живыми Go API и PostGIS. API по умолчанию не настроен; вымышленных участников или рейтингов нет.
- Production release APK/AAB, магазин и проверка обновления с production ключом.

Нет пошагового маршрутизатора, офлайн перепрокладки, спутниковой отправки сообщений или SOS. Очередь не означает доставку, офлайн состояние не разрешает старт. Минимум группы — четыре человека всего, включая гида; ограничения и допуск подтверждает сервер.

Скрипт готовит каталог и ресурсы, выполняет Python/Node/JVM тесты, собирает обе ABI версии и тестовый APK, сжимает ZIP без изменения payload, выравнивает, подписывает тем же debug-ключом и проверяет подписи и содержимое. `.github/workflows/android.yml` синхронизирован с `tools/android-build/github-actions.yml`; workflow собирает preview artifacts и не публикует релиз. Сам CI run в этой сессии не запускался. Для реального выполнения пяти сценариев добавлена отдельная manual-only задача `instrumentation` с параметром `run_instrumentation=true`, одним API 35 x86_64 AVD/KVM и лимитом 25 минут. YAML и shell syntax проверены; восемь синтетических JUnit fixtures проверили запрет ложного успешного результата. Это подготовка проверки, а не подтверждение device execution. Настоящий результат должен появиться в артефакте CI после отдельного успешного запуска.

На отдельно подключённом тестовом устройстве:

```bash
cd android
./gradlew connectedDebugAndroidTest
```
