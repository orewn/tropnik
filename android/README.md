# Тропник для Android

Приложение на Kotlin, Jetpack Compose и Room. Аккаунт, походы, чаты, органы управления и локальное хранилище реализованы средствами Android. Карта использует собственный `CustomMapEngine`, общий с веб-версией, в отдельном ограниченном системном WebView. Её сетевой посредник допускает только публичные картографические источники; интерфейс сообщений привязан к точному origin. Токены аккаунта в карту не передаются. Дополнительный экран «3D ландшафт» остаётся отдельным автономным WebView без сетевого доступа и интерфейса сообщений карты.

Интерфейс использует общую палитру Тропника, локальный Manrope с кириллицей, собственные векторные пиктограммы и элементы управления со скошенными углами. Минимальная область нажатия кнопок и переключателей составляет48dp. Неактивное действие, ожидание ответа, отсутствие подключения и ошибка сервера отображаются отдельными состояниями.

Подготовленные исходники следующего выпуска: **0.4.31-preview**, `versionCode=14`. Встроены **685 справочных карточек: 624 с исходной геометрией и 61 без подтверждённой линии**; отдельно остаётся учебная карточка. 624 файла соответствуют 621 уникальному источнику, 22 456 исходным частям и 404 749 вершинам. Доступны 15 туристических направлений и все 85 территорий существующей карты. Поиск и принадлежность к регионам индексируются на ревизию каталога; общий слой троп получает ровно те же ID, что и список. Изменение фильтра, слоёв или режима не переоткрывает WebView и не переустанавливает камеру.

Главная карта предлагает **«Рельеф», «Спутник» и «Тропы»**. Используются общий `TrailOverlayLoader`, исходные SHA-256 и прежние бюджеты: не более двух одновременных чтений подробных треков, 64 подробных источников и 180 000 точек в их кэше. Обзор всех исходных частей встроен отдельно; подробные GeoJSON переиспользуются без второй копии. Выбор нарисованной тропы проходит через геометрический hit test общего движка и проверку ID текущего фильтра в native. Для «Чёрного ключа» передаётся только capability, выданная общей проверкой точного source SHA и исходных координат; береговая маска и остальные маршруты не изменяются.

После остановки процесса карты системой кнопка повторного открытия восстанавливает последнюю принятую камеру для того же маршрута или региона: центр, масштаб и поворот. Первые кадры нового WebView не затирают этот снимок; прежняя GPS-точка не запускает повторное центрирование. При смене маршрута применяется его собственный обзор. В устройственный сценарий включены реальное завершение процесса WebView и проверка восстановленной линии и камеры; его прохождение подтверждает только отчёт финального APK.

**Сборка, 9 сценариев API 35 и публикация 0.4.31 пока ожидают проверки точного финального артефакта.** Последний подтверждённый baseline — [0.4.30: 51 JVM-тест и 8 сценариев API 35](../docs/release-0.4.30.md). Опубликованный APK до новой проверенной поставки остаётся **0.4.25-preview / code 13**, с debug-подписью, согласно [публичному манифесту](../web/public/downloads/android-manifest.json). Номер исходников не подтверждает сборку или установку. `BUILD-VERIFICATION.md` и прежние журналы сохраняют свои исторические версии.

## Составные походы (добавлены в 0.4.16)

Карточка **Составной поход** доступна в каталоге и во всех справочных карточках с исходной геометрией. Кнопка открывает объяснение, после которого пользователь может перейти в системный браузер или отменить переход. Для карточки передаётся только её публичный идентификатор: `https://orewn.github.io/tropnik/planner/?route=…`. Серверные маршруты аккаунта, учебная карточка и записи без линии не передаются в конструктор.

Конструктор позволяет соединять соседние и пересекающиеся тропы, выбирать точки и этапы, распределять путь по дням, сохранять планы и выгружать JSON/GPX. **Он работает в браузере и требует сети для загрузки. Планы сохраняются в хранилище этого браузера.** Перенос между устройствами выполняется через JSON. Это доступ к веб-конструктору из Android; нативный офлайн-конструктор и общая база браузерных планов с Room не заявляются. Отсутствие браузера или системный запрет перехода показывает ошибку в диалоге, сохраняя возможность отмены.

APK остаётся **preview с отладочной подписью**, а не production-поставкой с постоянным release-ключом. Номер версии сам по себе не гарантирует установку поверх предыдущего preview: совместимость зависит от совпадения identity и сертификатов. Публичный проверяющий скрипт берёт baseline из закоммиченного `web/public/downloads/android-manifest.json`, сверяет его с историческими исходниками и сравнивает applicationId, сертификат и versionCode. Даже совпадение этих условий не заменяет испытание обновления; `compatibleWithPreviousPreview=false` остаётся консервативным статусом до такого испытания. Нативного экспорта/импорта Room-данных сейчас нет; удаление приложения стирает его локальное хранилище. Не удаляйте предыдущую установку с нужными данными ради нового preview. Планы браузерного конструктора имеют отдельное браузерное хранилище и JSON-экспорт, который не переносит нативные закладки, пакеты или очередь сообщений.

## Запуск и сборка

Нужны JDK 17+, Android SDK platform 36, build-tools 36.0.0. Минимальная версия устройства — **Android 8.0 / API26**. APK ориентирован на target SDK36. Установите Android SDK стандартными средствами Android Studio или `sdkmanager`, примите лицензии SDK и укажите `ANDROID_HOME`.

Для генерации каталога, общего runtime карты и локальной сцены нужны Python 3.12+, Node.js не ниже 22.13 (CI использует 24), закреплённые зависимости `web`, NumPy и Pillow. TypeScript и Vite берутся из `web/node_modules` после установки по lockfile. Версии Python-инструментов закреплены в `tools/android-build/requirements.txt`; они не входят в APK. Из корня проекта перед первой Gradle-сборкой:

```bash
python3 -m pip install -r tools/android-build/requirements.txt
node tools/android-build/prepare-catalog.mjs
python3 tools/android-build/prepare-landscape.py
node tools/android-build/prepare-custom-map.mjs
node tools/android-build/prepare-catalog.mjs --check
python3 tools/android-build/prepare-landscape.py --check
node tools/android-build/prepare-custom-map.mjs --check
```

Генераторы не скачивают данные: `prepare-catalog.mjs` переносит фактические экспорты веб-каталога, обзор общего слоя и сохраняет побайтно все GeoJSON; `prepare-landscape.py` повторно вычисляет и сверяет производную сетку через `tools/map-package/refine_terrain.py`, копирует исходный DEM только по manifest allowlist, создаёт автономный HTML и точные CSP хэши его скриптов и CSS. `prepare-custom-map.mjs` собирает общий движок и native-контроллер, связывает исходники хешами и формирует закрытый реестр ресурсов, включая канонические URL троп. `--check` проверяет совпадение с текущими источниками без записи. При локальной разработке полный `build.sh` сначала обновляет производные файлы, затем выполняет проверки, JVM тесты и обе ABI сборки.

В GitHub Actions `build.sh` запускает генераторы только с `--check`: устаревшие данные должны остановить CI до Gradle, а не молча переписать поставку. До проверки данных, при создании build receipt и перед использованием APK в устройственных тестах или публикации сверяются `HEAD`, `GITHUB_SHA` и неизменность исходников Android, инструментов и общих картографических входов. Изменённые, добавленные в индекс и неотслеживаемые входные файлы блокируют подтверждение commit; игнорируемые кэши и каталоги отчётов ему не мешают. Обновлённые генератором данные нужно закоммитить до запуска CI. Локальная сборка без идентификатора CI остаётся рабочим preview и не допускается к публикации через release pipeline.

```bash
cd android
./gradlew :app:assembleDebug :app:testDebugUnitTest
```

APK появится в `app/build/outputs/apk/debug/app-debug.apk`. Универсальная сборка содержит `arm64-v8a`, `armeabi-v7a`, `x86_64`. Отдельная сборка для современных 64-битных ARM телефонов:

```bash
./gradlew :app:assembleDebug -PtargetAbi=arm64-v8a
```

Она перезаписывает тот же `app-debug.apk`, поэтому универсальный APK нужно скопировать до второй команды. Полный скрипт `tools/android-build/build.sh` выполняет обе сборки, unit-тесты, lossless Deflate9 с проверкой SHA256 каждого распакованного ZIP entry, повторное выравнивание и подпись тем же локальным debug-ключом, проверку подписи, ZIP alignment для страниц16КБ и целостность встроенной карты. Итоговые файлы размещаются в `android/dist/`.

Для прямого скачивания `.so` библиотеки сжаты в APK через стандартный `jniLibs.useLegacyPackaging=true`. Android распаковывает их при установке: загрузка меньше, установленное приложение занимает дополнительное место. Сам ELF каждой64-битной библиотеки проверяется на выравнивание16КБ отдельно от ZIP. Это не заменяет испытание на реальном устройстве16КБ. Документация: https://developer.android.com/guide/practices/page-sizes.

Gradle wrapper8.13 содержит закреплённую SHA256 официального дистрибутива. Зависимости и версии заданы в Gradle, серверные пароли и релизные ключи отсутствуют. Приватный ключ debug-сборки создаётся локально Android toolchain и **не входит в исходники**. Для публичного выпуска нужен собственный release signing, процедура обновления и проверка приложения на физических устройствах.

## Подключение сервиса

По умолчанию адрес API пустой. Во вкладке **Профиль → Подключить сервис** можно указать HTTPS origin или путь, заканчивающийся `/api/v1`. Альтернатива при сборке:

```bash
./gradlew :app:assembleDebug -PapiBaseUrl=https://your-domain.ru/api/v1
```

Это публичный адрес, а не секрет. В APK не нужно встраивать токены или ключи. HTTP, userinfo, параметры запроса и фрагменты в адресе запрещены. Серверный сертификат должен доверяться системным хранилищем Android. Редиректы и автоматические HTTP повторы отключены. Native API использует Bearer сессионный токен; cookie/BFF/CSRF браузера здесь не используются.

Готовность проверяется при запуске/восстановлении сети, смене адреса и нажатии **Обновить**: `OnlineViewModel.refreshData → ApiClient.checkHealth → GET /api/v1/health/ready`. Backend вызывает `DB.Ready`, проверяющий доступ к базе и версию схемы. Надпись **API и база данных готовы** появляется только после HTTP200 с `data.status="ready"` и `meta.mode="production"`. Liveness,503,204/202, посторонний или неверный JSON не подтверждают готовность. Проверка публичная и не отправляет сессионный токен.

В интерфейсе отдельно показаны состояние сервиса, наличие входа в аккаунт и время обновления данных. Сохранённый адрес или timestamp старых данных не означают подключение. При смене состояния сети готовность сбрасывается; отсутствие сервиса или авторизации не мешает автономной карте.

Клиент реализует регистрацию туриста/гида, вход/выход, редактирование профиля, опубликованные маршруты, набор без даты, создание похода проверенным гидом, присоединение/выход, roster назначенного гида, check-in, переходы статуса, отзывы подтверждённых участников и переписку. Ответы403/409/429, отсутствие сети, истечение сеанса и отсутствие публикаций отображаются явно. Роль `guide` при регистрации не является допуском.

Личный кабинет получает с API реальные статистику, награды, уведомления, свои обращения, решения модерации и апелляции. Пользователь может пожаловаться на сообщение/отзыв и подать апелляцию. Автоматические ограничения сервера не обходятся. Роли `staffRole` (модератор/администратор) и турист/гид независимы; нативное приложение не выдаёт себе полномочия. Операторская консоль доступна в веб-клиенте. Баллы за опасные выходы, вымышленные награды и рейтинги отсутствуют.

Правило продукта: минимум4 человека **всего, включая гида**. Более строгие ограничения маршрута приходят с API. Подтверждение места, фактического присутствия и старта делает только сервер. Приложение не превращает офлайн очередь в разрешение похода.

## Что работает без интернета

- Встроенный обзор России, 15 туристических направлений и 85 территорий существующей карты. Выбор списком и на карте использует один каталог.
- Локальный обзорный рельеф всей выбранной области России: 341 PNG256 тайл z0–4, 1 689 348 байт тайлов, полный пакет из 344 файлов — 1 759 234 байта. Он создан из Natural Earth, хранится в `maps/russia-relief/` и служит обзором и запасной подложкой до готовности подробного покрытия. Это изображение широких форм местности, не высотная сетка и не подробная подложка всей страны. Режим **Рельеф** использует его на обзоре и локальную DEM-отмывку в подготовленной области Бзерпина.
- Область показа ограничена общим с вебом набором геометрии: за её пределами подложку, подписи и линии закрывает непрозрачная маска. Камера ограничена охватывающим прямоугольником; нажатия и GPS-точки дополнительно проверяются по настоящим Polygon/MultiPolygon. Чукотка у линии смены дат учитывается отдельно. Это исторический источник для выбранной области показа, а не утверждение о юридических границах или точности навигации.
- 685 справочных карточек доступны локально: для 624 включены исходные GeoJSON, ещё 61 показана без геометрии. Общий слой рисует 621 уникальный источник и сохраняет разделение исходных частей. К карточкам добавлена одна ясно обозначенная учебная запись без выдуманной тропы. Все карточки остаются `fieldVerified=false` и `navigationReady=false`; неизвестные параметры не заполняются расчётами из линии. Диапазоны длительности сохранены текстом, официальные доказательства показывают свой ограниченный scope. Фильтр региона учитывает `regionIds`.
- Локальная векторная подложка пилотной области Бзерпинского карниза:193тайла, z7–14, bbox `[40.29,43.64,40.49,43.82]`. Глифы кириллицы, стиль и необходимые GeoJSON входят в APK.
- Рельеф этой же области: 21 локальный тайл Terrarium PNG256 на z7–12. Собственный worker вычисляет отмывку и горизонтали из измеренных высот; свет задан в географических координатах. В главной карте используются режимы рельефа и спутника. Ранее поставленная объёмная сетка остаётся отдельным действием в локальном просмотрщике карточки Бзерпина.
- Отдельная автономная3D сцена Бзерпина использует общие с вебом renderer и производную сетку **513×513 /263 169 высот**, заново проверенную по архивным DEM тайлам. Шаг выборки около31,42×39,14м; он не означает новую съёмку или более высокую измерительную точность. Исходная сетка129×129 и все исходные тайлы сохранены. HTML содержит код, высоты, геометрию и шрифты; освещение следует камере автоматически. WebGL используется при доступном графическом backend, предусмотрен программный fallback.60fps на Android не измерены и не заявляются.
- Закладки и сохранение/проверка/открытие/удаление локального пакета. Региональный пакет v2 хранит каталог, атрибуцию и точные исходные линии выбранной области. Общий renderer, обзор, покрытие и пилотные тайлы остаются в APK; их полный набор и SHA256 берутся из `custom-map/manifest.json`, без повторного копирования в каждый регион. Все файлы пакета проверяются до публикации записи в Room.
- Разовое foreground измерение GPS при явном разрешении; нет фонового отслеживания или отправки геопозиции на сервер.
- Ранее полученные сообщения своего аккаунта: зашифрованный кэш текущей беседы. При синхронизации обновляется весь последний блок100 сообщений, чтобы решения модерации заменяли прежний текст; локальный защитный предел составляет500 сообщений. Новое сообщение можно поставить в очередь; оно явно помечено **не доставленным** до ответа API. Повтор использует тот же `clientId`.

Встроенная подробная офлайн-подложка **не покрывает Хосту/маршруты 16А, 16Б, весь Краснодарский край или Россию**. Вне пилотной области без сети остаются общий обзор и исходные линии каталога. Показанная геометрия не является сертифицированной навигацией. Нет пошагового маршрутизатора, офлайн перепрокладки, автоматически вычисленного профиля высот, подтверждения актуальной погоды или спутникового SOS.

Пакет рельефа основан на Mapterhorn/Copernicus GLO-30. Это модель поверхности с номинальным исходным шагом около 30 м, включая влияние растительности и сооружений, а не свежая съёмка 2026 года. Она не показывает текущую проходимость, лавинную обстановку или границу закрытого участка. Диапазон сетки 551,4–3231,1 м относится ко всей пилотной области, не к проверенному профилю маршрута. Объёмная модель доступна в отдельном локальном просмотрщике с собственной WebGL/Canvas-отрисовкой.

Экономный режим нативной карты ограничивает целевую частоту кадров30; на устройствах с малым объёмом памяти он выбран по умолчанию. Это настройка нагрузки, а не гарантия измеренной производительности.

При открытии карточки8А документ проверяется по SHA256, лимиту2МиБ и связи с исходным DEM. Один прикреплённый WebView готовит первый кадр за непрозрачной карточкой. Кнопка3D включается после сигнала renderer и `postVisualStateCallback`; открытие и возврат сохраняют тот же WebView и позицию списка. Готовая скрытая сцена приостанавливается, незавершённая подготовка отменяется при уходе в фон и может быть повторена после возврата. Во время полноэкранной сцены заголовок/нижняя навигация скрываются, основной MapView карточки освобождается. При закрытии карточки уничтожаются viewer, callbacks и observer; потерянный WebView после `onRenderProcessGone` не используется снова.

Если сцена отказывает после первого кадра, документ снимает готовность; видимый viewer проверяет её каждые 500 мс. Сломанный WebView освобождается, а кнопка **Подготовить сцену заново** создаёт новую сессию из проверенного документа. Поздний callback прежнего renderer не возвращает готовность. Скрытая готовая сцена остаётся приостановленной без периодического опроса.

Сохранение офлайн-пакета проверяет скопированные файлы до публикации в Room. Короткая секция публикации завершается без отмены и отмечает каталог как опубликованный до возвращения управления. Отмена копирования по-прежнему распространяется вызывающему коду; после успешной публикации она не удаляет каталог, на который уже указывает база. Неудачная очистка старой копии также не затрагивает новый пакет.

Кнопка **Открыть** заново читает актуальную запись Room под тем же mutex и проверяет весь обязательный набор региональных файлов и привязку к общему runtime. Затем карточки и исходные UTF-8 линии берутся из сохранённой копии; линии удерживаются в памяти до передачи движку. Переход из карточки на карту и назад сохраняет этот контекст. Обычная смена экрана или региона возвращает текущий каталог приложения. Удаление файлов, другой каталог или другая ревизия runtime не получают статус готовой области. Для изменившегося приложения предлагается **Обновить**, для повреждённой копии сообщается отдельная причина. Пакеты v1 распознаются и проверяются прежним читателем; перед открытием новым движком они требуют обновления. Перезапись атомарна, отдельно сохранённые карточки при удалении области остаются.

Маршрут8А с27октября2026 открыт только до Бзерпинского карниза; лагерь Холодный закрыт согласно сообщению заповедника от26октября2026. Полная исходная OSM геометрия показана справочно. Граница закрытого сегмента не выдумана. Условия нужно проверять заново перед выходом.

## Приватность и состояние

Сеанс и тексты чатов шифруются AES-GCM ключом Android Keystore. Кэш и очередь разделены по origin сервиса и пользователю. Токен не попадает в URL. Пароль не сохраняется. `allowBackup=false`; cleartext transport запрещён. Геопозиция остаётся локально.

Локальная3D сцена не получает объекты Android, геопозицию или данные сеанса. Сеть, файловый/content доступ, новые окна и разрешения WebView блокируются. CSP разрешает только точные SHA256 встроенных скриптов/CSS и встроенные шрифты. Native код отправляет фиксированные события pause/resume и читает признак готового кадра; JavaScript interface отсутствует. Глобальные cookies и таймеры других WebView не меняются. Скрытый viewer не принимает пользовательский ввод или фокус и исключён из accessibility ветки.

Выход удаляет локальный токен, личный кэш и очередь. Если API не подтвердил отзыв сеанса204, интерфейс сообщает об этом честно. Чат использует HTTPS, **не E2EE**. Сервер обрабатывает содержимое. Телеметрии и рекламных SDK нет.

После смены сервиса старые публичные карточки остаются закладками со своим origin. Действия по ним требуют подключения исходного сервиса. Неподключённый backend означает пустое социальное состояние; приложение не создаёт вымышленных людей, рейтинги или ответы.

## Подробная карта при наличии сети

Переключатель **Сеть** относится только к подложке карты и не означает готовность социального API. При подтверждённом Android доступе в интернет закрытый сетевой посредник допускает только перечисленные публичные URL OpenFreeMap, Mapterhorn и EOX. В режиме **Рельеф** общий worker декодирует векторные тайлы и высоты; в режиме **Спутник** общий движок выбирает рассмотренный источник EOX Sentinel либо Blue Marble для предусмотренной области у линии смены дат. Подпись источника относится к реально принятому полному кадру. Источники и лицензии доступны в окне информации; токены аккаунта этим серверам не отправляются.

При отсутствии сети, ограниченном соединении или выключенном переключателе native-посредник запрещает удалённые запросы и отменяет прежние. Общий движок сохраняет готовую подложку, локальные линии и доступную подробную пилотную область. Спутник не заявляется автономным; выбранный спутниковый режим может продолжить загрузку после восстановления связи. Ошибка отдельного тайла не отключает другие разрешённые источники. Незавершённая замена не считается готовым изображением; повторная попытка сохраняет камеру. Некорректные локальные байты и ошибки геометрии показываются отдельно.

Сетевые источники стоят ниже локального пилота, маршрута и последней RF-маски. Полная подробная карта страны офлайн не заявляется; скачивание регионов с этих общедоступных сервисов не выполняется. Серверный URL API остаётся пустым до настройки пользователем.

## Проверки

JVM тесты проверяют HTTPS адреса, защиту пути, API Bearer/ошибки версий/идемпотентный идентификатор сообщения/курсоры/logout204, а также повреждение, усечение и выход пути за границы offline пакета.

`BundledMapRuntimeTest` исполняет контракт на фактическом renderer-manifest и всех его assets, включая overview, RF coverage, каталог, пилот и высоты; он отклоняет подмену, усечение, небезопасный путь и превышение бюджета. `OfflinePackIntegrityTest` проверяет v1/v2, обязательный каталог и атрибуцию, symlink, размеры и сохранение исходных UTF-8 bytes при чтении снимка. `MapCameraCheckpointTest` проверяет безопасные координаты камеры, immutable JSON и восстановление только того же выбранного маршрута.

Тесты TLS MockWebServer проверяют корректный ready-ответ без Bearer, недоступность базы 503 и ложные успешные ответы: liveness вместо readiness, preview/неполный/ошибочный JSON, HTML, 204 и 202. JVM-проверки покрывают настоящий документ сцены, повреждение/усечение, stale DEM, недопустимую entrypoint/размерность/provenance, географические ограничения и безопасную публикацию офлайн-пакета. Фактические результаты baseline — в [журнале 0.4.30](../docs/release-0.4.30.md). Эти результаты не переименовываются в проверку исходников 0.4.31.

Отдельная проверка APK сверяет SHA256193векторных и21высотного тайла, лицензии/глифы, исходную сетку129×129 и фактически встроенную в HTML производную513×513, её пространственные метаданные/provenance, локальные URL, два разрешённых online endpoints, все геометрии действующего манифеста каталога и точные CSP хэши. Проверяются выравнивание ELF LOAD сегментов64-битных библиотек, подключение native DEM и camera-relative hillshade. Это статические проверки содержимого, а не запуск на телефоне или испытание GPS в походе.

`MapStylePolicyTest` проверяет допуск подключения при offline/limited/user-off/failure, parsing длительности/регионов и карточки без геометрии. `CustomMapResourcePolicyTest` проверяет точные origin/path и отказ в доступе к credentials, query, traversal и посторонним провайдерам. Node-проверки native-контроллера исполняют настоящий общий загрузчик на всех 621 источнике, проверяют фильтры и карточки без линии, source SHA и береговую capability, отмену поздних результатов и восстановление выбранного режима без сброса подложки.

Четыре `BrowserPlannerTest` проверяют точный HTTPS origin конструктора, соответствие всех разрешённых Android-ссылок фактическим ключам веб-графа, исключение учебных/серверных/неизвестных карточек и безопасное кодирование идентификатора в query. Instrumentation-сценарий `browserPlannerExplainsStorageAndCanCancelWithoutLeavingTheApp` проверяет оба входа, объяснение браузерного хранения, передачу названия реальной тропы и отмену. Он не запускает внешний браузер и не обращается к конструктору по сети; работу веб-конструктора подтверждает отдельная веб-проверка.

Python проверки покрывают DEM allowlist, покрытие области, подмену и повреждение файлов/производной, повторяемость HTML и CSP. Пять дополнительных проверок обзорного пакета РФ сверяют все341PNG, manifest, порядок слоёв, ограничение масштаба и только локальные URL. Node проверки выполняют настоящий generated bootstrap с управляемым renderer: foreground preparation, отмену/повтор, ожидание первого кадра, reuse, ошибку и terminal failure после первого кадра. Поздние callbacks не могут вернуть failed-документ в ready. Проверки каталога сверяют все файлы с веб-источниками и отказывают при подмене параметров/URL, классификации территорий и удалении исходных данных их принадлежности; две ZIP-проверки подтверждают точный payload после сжатия. Эти проверки не имитируют Android compositor или графический драйвер.

Три `CatalogSearchTest` сравнивают новый индекс с прежним порядком результатов на всём встроенном каталоге, проверяют пересоздание индексов для новой ревизии и защиту результата от изменения вызывающим кодом. Четыре Node-проверки генератора проверяют пересечение территорий, точное написание ID и карточки без придуманной геометрии.

Инструментальные Compose тесты находятся в `app/src/androidTest`. Они проверяют местную карточку с ограничением, отсутствие входа при пустом API, готовность сцены до открытия, reuse после возврата, ориентацию и обработчик потери renderer. Сценарий потери процесса вызывает callback напрямую, а не уничтожает системный процесс. Добавлен пятый сценарий document failure после первого кадра с повторной подготовкой на новом WebView; реальный GPU-сбой он не имитирует. Сценарий `nationalTerritoryCatalogueCanOpenSaveAndReturnToItsSourceRoute` переключает каталог, находит реальный маркер новой территории через инспекцию собственного движка, нажимает на него настоящим MotionEvent, открывает и сохраняет карточку и проверяет возврат. Для выполнения нужен запущенный эмулятор или подключённый тестовый телефон:

```bash
./gradlew connectedDebugAndroidTest
```

Для проверки офлайн запустите их и вручную откройте пилотную карту при отключённых Wi-Fi/мобильных данных. Сборка тестового APK сама по себе не означает выполнение этих проверок. Фактические результаты конкретной сборки фиксируются отдельно в журнале её выпуска; `BUILD-VERIFICATION.md` описывает историческую сборку.

## Проверка на эмуляторе в GitHub Actions

Workflow `.github/workflows/android.yml` и его исходный шаблон `tools/android-build/github-actions.yml` содержат отдельную задачу `instrumentation`. Она входит в проверки push основной ветки и pull request. Для ручного запуска **Actions → Android preview → Run workflow** включается параметр **run_instrumentation=true**. Для dispatch workflow должен быть опубликован в основной ветке ([правило GitHub](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#workflow_dispatch)).

После успешной задачи сборки запускается один `ubuntu-24.04` runner, один API 35 `google_apis/x86_64` AVD и **десять** сценариев `LocalExperienceTest`. Девятый сценарий проверяет реальный общий слой, переключатель троп, сохранение камеры, совпадение фильтра с карточками и настоящий MotionEvent по нарисованной линии «Чёрного ключа» с последующим открытием карточки и проверкой береговой capability. Он также останавливает реальный WebView renderer и проверяет восстановление камеры и линии через пользовательскую кнопку. Offline-выбор спутника сохраняет доступную подложку; этот сценарий явно не подтверждает загрузку спутниковых сервисов по сети. Десятый сценарий отключает Wi-Fi и мобильные данные Android и нажимает реальные кнопки сохранения области, проверки и открытия. Он проверяет снимок и отображение исходной линии после удаления её файла уже после открытия, отказ следующего открытия повреждённой копии, обновление при смене runtime, удаление без потери закладки и повторную установку. Исполнение всех новых сценариев на финальном 0.4.31 ожидается. Использованы закреплённые commit SHA Actions и официальный SDK CLI. Задача требует KVM, VM acceleration и использует ANGLE поверх SwiftShader Vulkan (`swangle`) для графики ([GitHub runners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners), [Android acceleration](https://developer.android.com/studio/run/emulator-acceleration)). API origin остаётся пустым, поэтому локальные проверки не зависят от работающего backend.

Проверка требует все десять ожидаемых JUnit cases без пропуска, дубликатов или ошибок и успешное завершение инструментального запуска. Пустой отчёт, отсутствующий тест или одна лишь компиляция не дают `deviceExecutionVerified=true`. Идентичность исполненного APK и опубликованного бинарного файла определяется его SHA256, а не только версией или commit исходников.

Артефакт `tropnik-android-api35-instrumentation-…` содержит результаты, `device-result.json` с commit/run ID, логи эмулятора и WebView, доступные тестовые снимки и SHA256 действительно запущенных APK. Сценарии документируют поведение Android UI, но не подтверждают работу физического GPU, полевой GPS, батарею или живой backend. Фактический результат новой версии указывается в её релизном отчёте; старый `docs/verification/android-instrumentation-workflow-check.json` не удостоверяет исполнение новых сценариев.

## Источники и лицензии

`app/src/main/assets/SOURCES.txt` содержит первоисточники, лицензии, даты и ограничения. На карте постоянно видна компактная подпись **© OpenStreetMap contributors**; соседняя кнопка информации открывает полную атрибуцию OpenStreetMap/OpenMapTiles/OpenFreeMap и источники. В приложении также доступна кнопка **Источники и лицензии**. ODbL данные отделены от аккаунтов и кода, но такое разделение само по себе не отменяет лицензионные обязанности.

Геометрия области показа хранится в `assets/maps/russia/`: канонические area/mask и provenance с SHA256, датой источника, описанием охвата и исключениями. Использованы geoBoundaries/OSM/Wambacher, данные за2017год, ODbL1.0. Нативный генератор берёт те же артефакты из `web/public/data/`, проверяет их хеши и ставит маску последним слоем без обводки. Исходный большой GeoJSON и рабочие геометрические кеши в APK не включаются. Точки каталога с идентификаторами, явно исключёнными в provenance, не допускаются проверкой пакета.

Для рельефа сохранены атрибуция Mapterhorn/Copernicus, обязательное уведомление об ответственности и оригинальная лицензия Copernicus GLO-30. PDF можно открыть из окна источников без сети через установленный на устройстве просмотрщик. FileProvider предоставляет только выбранный файл из отдельной папки лицензий, а не данные приложения. Лицензия Manrope OFL также входит в APK; прежние картографические SDK и их runtime больше не поставляются.

Пилотный пакет скачан по разрешённой на момент загрузки политике OpenFreeMap: ограниченная область,193тайла, меньше50МБ, не более4параллельных запросов, уникальный User-Agent. Локальный режим не обращается к сетевым источникам. Отдельно включаемая подробная онлайн-подложка использует задокументированные OpenFreeMap/Mapterhorn endpoints без массового скачивания. Production каталог пакетов требует собственного контролируемого pipeline и обновлений условий/лицензий.
